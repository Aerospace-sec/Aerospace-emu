# 航空协议安全众测锦标赛初赛赛题总结

> 整理依据：比赛初赛赛题 PDF，以及仓库中的 `needed.txt` 和 `Aerospace-needed.txt`。本文件是团队任务索引，不替代组委会正式赛题；若正式题目更新，以组委会版本为准。

## 一、比赛题型与分值结构

### 类型一：航空协议安全分析

各队抽签确定两道必答题和一道选答题：

- 必答题：每道 40 分；
- 选答题：每道 20 分；
- 附加题：可从类型一全部题目中自选一题，最高 20 分，超过一题的部分不计分。

每道类型一报告至少覆盖：原生设计、设备实现、配置部署、攻击实现、业务影响、验证思路和缓解措施；不能只写通用 IT 漏洞。

### 类型二：具体场景网络安全风险链路分析

三道均为选答题，每道 20 分。要求从明确入口开始，构造贴合民航架构的跨域跨协议风险链路，并量化设备成本、技术门槛、时间成本、接入难度、检测概率和业务影响。

### 类型三：脆弱性缓解与安全管控方案

- 第 1 题为必答题，40 分；
- 第 2、3 题为选答题，每道 20 分。

缓解方案必须关联具体脆弱性和攻击链，说明检测、防护、响应、恢复、部署成本、实时性/确定性影响和合规依据。

## 二、类型一题目清单

### 第 1 题：ARINC 664（AFDX）协议脆弱性深度分析

**场景：** 机载航电核心域 AFDX 确定性以太网，承载飞控、航电综合处理、座舱显示等关键系统实时数据。

**重点：**

1. 虚拟链路（VL）调度、带宽分配、BAG、冗余管理和双链路机制的原生脆弱性；
2. 端系统协议栈和 AFDX 交换机的内存破坏、逻辑缺陷、边界校验缺失等实现问题；
3. VL 配置表、BAG、冗余参数不当引发的配置脆弱性；
4. AFDX 与 ARINC 429、ARINC 825、维护域、客舱域交互边界的脆弱性。

### 第 2 题：ARINC 429 总线脆弱性深度分析

**场景：** 传统机载航电单向数据广播总线，用于大气数据、惯导、飞控、发动机控制等单元间传输。

**重点：**

1. 单向广播、无握手、无原生源认证和完整性保护、32 位字、奇偶校验及双速率机制；
2. 物理总线接入、监听、注入以及多接收器架构下的差异；
3. 注入、拒绝服务、重放的触发条件和技术路径；
4. 与核心航电计算单元、数据采集单元的交互脆弱性及级联影响。

本仓库已有：`sim/arinc429_lab.py`、`report/arinc429_security_report.md`。

### 第 3 题：以太网、FTP、UDP、SNMP、ARINC 615A 协议脆弱性深度分析

**场景：** 机载维护网、客舱娱乐网、地面保障网，承载数据加载、设备状态监控和客舱业务。

**重点：**

1. IEEE 802.3 在物理、链路、网络、传输层的航空部署脆弱性；
2. FTP 明文、认证、访问控制、命令执行、主动模式端口跳转和 ARINC 615A 数据加载风险；
3. UDP 无连接、无状态、伪造、放大、重放对实时确定性和可靠性的影响；
4. SNMP 管理面认证、授权、配置变更和监控边界；
5. 以太网维护域、客舱域与航电核心域的隔离和跨域风险。

### 第 4 题：ARINC 825 总线脆弱性深度分析

**场景：** 基于 CAN 的机载通用数据总线，用于航电、客舱和电源系统的分布式节点通信。

**重点：**

1. CAN 仲裁、标准/扩展帧和错误处理机制；
2. 监听、注入、重放和错误触发型拒绝服务；
3. 分布式节点劫持、权限提升和横向渗透；
4. 异常数据对电源管理、客舱控制等业务的影响。

### 第 5 题：USB 接口脆弱性深度分析

**场景：** 机载维护 USB 与客舱乘客 USB 两类接口。

**重点：**

1. 维护接口与客舱接口的部署、权限和隔离差异；
2. 设备枚举、数据传输、供电和厂商实现全流程；
3. BadUSB、固件攻击、枚举欺骗、数据注入、权限提升和恶意代码加载；
4. USB 与机载计算单元、维护系统交互的边界控制。

### 第 6 题：RS-422、RS-232 等串行接口脆弱性深度分析

**场景：** 机载航电单元间及机载设备与维护设备间的差分串行全双工通信。

**重点：**

1. 差分传输、全双工和无原生认证/加密/访问控制的设计缺陷；
2. 航电系统、维护系统的部署和接口配置；
3. 物理接入、监听、注入、篡改和重放；
4. 异常数据对航电交互和维护操作的影响。

本仓库已有：`sim/serial_lab.py`、`report/serial_interface_security_report.md`。

## 三、类型二题目清单

### 第 1 题：物理接口接入型跨域攻击链

从机载物理维护接口（USB、RS-422、以太网维护口等）进入维护域，最终影响航电核心域。必须贴合真实机载网络架构，所有漏洞应继承类型一分析成果。

### 第 2 题：无线空口接入型跨域攻击链

从客舱 Wi-Fi、ADS-B、卫通空口等进入空地通信域或客舱域，最终影响航电系统或地面运营系统。必须说明设备门槛、空口传播约束和可行性。

### 第 3 题：地面网络接入型跨域攻击链

从地面保障网络或空管地面网络进入，经数据加载、ACARS、ADS-B 地面接收等业务流程，最终影响航电系统或空管运行。

本仓库已有防御性链路报告：`report/chain3_ground_network_attack_chain.md`。报告只使用合成模型，不代表真实系统已经被攻破。

## 四、类型一选答题清单

### 选答 1：ADS-B 广播式自动相关监视

分析 1090 MHz ES 明文广播、无原生认证、虚假目标、位置/身份欺骗、篡改、重放、射频干扰，以及 ADS-B IN 与地面接收系统的差异和空管级联影响。

### 选答 2：ACARS / 航空卫星通信

分析空地双向报文的认证、加密、地址解析、路由转发，VHF/卫星/HF 传输差异，监听、篡改、注入、劫持、重放和航务影响。

### 选答 3：GPS 全球定位系统

分析民用 L1 明文和无原生认证、捕获跟踪解调定位解算全流程，转发式/生成式欺骗、压制式/欺骗式干扰、重放及组合导航影响。

### 选答 4：Wi-Fi（IEEE 802.11）

分析客舱 Wi-Fi 与地面维护 Wi-Fi 的部署差异，弱配置、Evil Twin、接入控制、管理帧、监听、劫持、中间人、拒绝服务和航电边界隔离。

### 选答 5：5G-ATG

分析机载终端、地空基站、专属核心网和地面应用的全链路，空口/信令/数据保护，干扰、空口劫持、伪基站、篡改、注入、监听及与航电/客舱/运营系统的边界。

本仓库已有：`sim/atg5g_lab.py`、`report/5g_atg_security_report.md`。

## 五、类型三题目清单

### 第 1 题：高风险脆弱性针对性缓解方案

针对类型一漏洞逐条提出缓解措施，明确漏洞编号、缓解效果、部署成本、对实时性/确定性的影响和合规符合性。

### 第 2 题：跨域攻击链全链路纵深防御方案

针对类型二链路各节点分别提出检测、防护、响应、恢复措施，形成完整阻断方案，同时兼顾实时性、可用性和安全性。

### 第 3 题：机载与空地通信全生命周期安全管控体系

覆盖事前防护、事中检测、事后响应，明确架构、技术手段、流程管控和 DO-326A、CCAR-25、民航网络安全规章等合规对标。

## 六、评审强制要求

所有报告必须遵守 `needed.txt` 与 `Aerospace-needed.txt`：

- 严格贴合民用航空机载航电、空管和地面保障场景；
- 不得用“存在欺骗风险”“有注入漏洞”等泛化句替代分析；
- 每条漏洞明确协议层级、触发条件、适配设备、利用前提、路径、影响、危害等级和验证思路；
- 所有标准、论文、CVE、技术结论和量化数据必须有来源；
- 危害统一分为：极高、高、中、低；
- 优先提供可复现实验、仿真或实测证据；
- 防御性表达，不提供真实航空器、公共频谱或生产网络的直接攻击指令；
- 缺失真实数据时标记为“工程推演”或“待实装验证”，不得把条件性路径写成真实系统已被攻破。
