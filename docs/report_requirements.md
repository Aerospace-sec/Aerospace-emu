# 赛题报告统一要求

本文件将 `needed.txt` 与 `Aerospace-needed.txt` 中的要求转成团队审查清单。原文件保留为需求基线，不应删除或改写；`needed.txt` 因本地工程规则默认不上传，正式交付前由团队安全保存并共享给授权成员。

## 1. 场景约束

- 必须贴合民用航空机载航电、空管或地面保障的真实业务场景。
- 必须说明设备、接口、协议、域、数据流和信任边界。
- 只罗列通用 IT 漏洞、缺少航空场景适配、违反机载架构或适航基本逻辑的内容不得作为有效结论。
- “进入地面网络”不能直接写成“进入航空器”；每个跨域边界必须单独证明。

## 2. 漏洞分析粒度

每条漏洞至少填写：

1. 稳定漏洞编号和名称；
2. 协议层级；
3. 原生设计、设备实现、配置部署或边界交互类别；
4. 资产、适配设备、接口和协议版本；
5. 触发条件；
6. 利用前提、所需身份、物理可达性和维护状态；
7. 逐步攻击/故障路径；
8. 设备成本、技术能力、准备/实施/保持访问时间；
9. 具体业务影响和级联影响；
10. 极高/高/中/低危害等级及升级/降级条件；
11. 被检测条件、日志/传感器和概率依据；
12. 验证思路、实际结果和证据路径；
13. 不成立条件、阻断点和待补真实系统证据；
14. 针对性整改。

禁止只写“存在欺骗风险”“存在注入漏洞”“可能导致失控”等泛化句。

## 3. 类型二攻击链强制字段

每条链必须包含：

- 民航业务场景和最终目标；
- 物理接口、无线空口或地面网络入口；
- 完整系统架构图和信任边界图；
- 编号化节点和边；
- 每个节点的资产、域、接口、协议和对应类型一漏洞编号；
- 攻击前/利用后权限、权限提升和横向移动方式；
- 触发前提、设备/技术/时间成本；
- 每一步可观测日志、告警和检测条件；
- 最终影响、级联影响和危害等级；
- 证据等级：本地复核、既有报告记载、工程推演、待实装验证；
- 不成立条件、阻断点和待补证据。

## 4. 风险量化

不得用 CVSS 直接代替航空业务风险，不得随意相乘虚构精确成功率。必须分别定义并给出依据：

- 设备成本；
- 技术门槛 1--5 级；
- 准备、实施和保持访问时间；
- 物理可达性、身份、维护状态和网络位置；
- 被检测概率区间及传感器/日志依据；
- 整条链的瓶颈步骤和攻击可行性；
- 极高、高、中、低业务影响；
- 物理接入、管理员权限、网关旁路、真实 ICD 等条件变化下的敏感性。

## 5. 证据与合规

- 标准、ARINC 规范、DO 系列、民航规章、论文、CVE 和技术结论必须注明来源。
- 实验优先：提供脚本、测试、日志、JSON、截图、模型版本和 SHA-256。
- 每条量化数据必须能追溯到来源或明确标记为分析估计。
- 缺失真实脚本、抓包、设备日志或台架数据时，保留结论但明确标记“既有报告记载”“工程推演”或“待实装验证”。
- 报告结论必须前后一致，漏洞、攻击链、缓解和证据必须闭环。

## 6. 安全边界

- 只使用离线图模型、状态机、可达性矩阵、故障注入和授权仿真。
- 不连接真实飞机、机场生产网、空管网、公共移动网络或公共频谱。
- 不提交真实凭据、真实 ICD、厂商保密资料或未经授权的设备数据。
- 不提供针对真实航空器、生产网络或公共频谱的直接攻击操作指令。
- 仿真结果不得表述为真实航空系统已经被攻破或已产生真实飞行后果。

## 7. 交付审查

提交前必须通过：

```bash
python3 -m pytest -q
python3 scripts/run_all_simulations.py --profile quick
python3 scripts/run_cross_model_chain.py --scenario normal
python3 scripts/run_cross_model_chain.py --scenario injection
git diff --check
```

PR 必须关联题目编号和责任人，至少一名非作者审查；安全结论、跨域链路和最终报告至少两名审查人。
