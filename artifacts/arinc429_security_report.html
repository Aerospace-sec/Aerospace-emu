题目： ARINC 429 总线脆弱性深度分析
版本： 1.0
日期： 2026-08-24
验证类型： 本地逻辑仿真；不连接真实航电设备
结论性质： 研究与竞赛验证结论，不构成型号适航批准或运行放行结论

摘要

ARINC 429 的原生 32 位字提供标签、SDI、数据、SSM 和奇偶校验，但没有密码学来源认证、消息新鲜度、保密性或总线级访问控制字段[1]。在民用航空机载架构中，这意味着：只要攻击者已经获得了能够驱动目标接收通道的物理或逻辑入口，接收端可能无法区分“合法发射 LRU 发出的、内容被篡改的、已捕获后重放的”字。

本报告不把“可以构造一个 32 位数”泛化为“飞机必然可被远程控制”。ARINC 429 通道通常是一个发射端向多个接收端的单向链路；攻击必须落在受损发射 LRU、维护/测试适配器、总线桥接器、线束/连接器或其后的系统边界上。实际影响还取决于机型 ICD、标签消费者、冗余/交叉校验、告警与失效降级逻辑。

本地仿真对一个合成标签 0o203 做了原生接收端与受控安全网关的对照。14 项自动化测试通过，实验记录见 artifacts/results.json 和 artifacts/experiment_log.md。关键结果如下：

场景 原生接收端 受控网关 证据含义
未授权来源注入 接受 拒绝：unauthorized_source 原生字不绑定密码学来源
捕获字重放 接受 拒绝：replay；过期另拒绝：stale 原生字无序号/时间戳
修改数据并重算奇偶 接受 拒绝：authentication 奇偶校验不是消息认证码
语义越界 接受 拒绝：semantic_range 原生格式不表达项目物理范围
64 字连续占线 合法帧从 20.48 ms 后才开始 合法帧 0 ms 开始 无入口过滤时可造成时延/可用性损失
100 kbps 接收、12.5 kbps 发送 不锁定有效字 由端口配置/物理监测处理 速率控制不属于 MAC 网关能力
被动观测 标签和数据可读 MAC 不提供保密 需要分区/密码封装或物理防护

1. 场景、系统边界与假设

1.1 典型民用航空场景

分析对象是民用运输类飞机上的机载航电数据传输：大气数据计算机（ADC）、惯性/姿态相关计算单元、飞行管理/显示计算单元、自动飞行相关计算单元或其他 LRU 之间，通过 ARINC 429 通道传递配置规定的参数。一个具体标签是否进入飞行导引、显示、告警、发动机控制或其他安全相关计算，必须以该机型的系统架构图、接口控制文件（ICD）、标签分配表和安全评估为准，本报告不自行假定 0o203 对应空速、姿态或任何真实参数。

地面保障路径只按以下有条件的架构讨论：维护人员使用经批准的地面保障设备（GSE）或测试适配器，在地面维护模式下接入数据装载/测试边界；该设备或边界可能驱动某个 LRU、桥接器或受控测试端口。并非所有飞机都向 ARINC 429 直接开放此接口，是否存在这条路径必须由机型维护手册、WDM、设备安装图和维护配置确认。

2. ARINC 429 协议原理

2.1 通道和传输组织

依据 ARINC 429 Part 1[1]，典型通道为单向传输：一个发射端向一个或多个接收端发送数据，接收端不通过同一数据字向发射端返回握手。正常设计以一个发射端为边界，接收端数量、线缆、端接和具体电气参数由设备安装与机型设计确定。该组织方式的安全含义是：

  1. 接收端通常按字内容和通道配置判断是否接收，不通过密码学方式判断“哪个物理源”发出了字。
  2. 原生协议没有类似共享介质竞争仲裁、消息优先级队列、窗口确认或重放计数器的安全机制。
  3. “攻击者注入”不能理解为任意设备在空中无线注入；它要求攻击者控制合法发送侧、替换/桥接发送侧，或获得能改变该物理通道的维护/测试入口。

2.2 32 位字格式

本报告仿真使用以下字段布局。字段编号沿用 ARINC 429 规范语义；代码内部用最低有效位表示字段数值，以便读写和测试，未模拟线上标签位反转及模拟电气波形。

规范字段 位范围 仿真含义 安全作用边界
Label 1--8 8 位标签，报告以八进制展示 表示数据类型/含义的配置索引，不是密码学来源认证
SDI 9--10 2 位源/目的标识语义 最多提供配置级区分；可被伪造，不是不可伪造身份
Data 11--29 19 位数据区 可表达 BNR、BCD 或离散数据，具体编码由 ICD/标签定义
SSM 30--31 符号/状态矩阵 表示状态/有效性等协议语义，不证明发送者可信
Parity 32 奇校验 发现部分传输错误，不提供认证、授权、保密或新鲜度

2.3 速率与字时长

ARINC 429 通道的典型标称速率为 100 kbps 和 12.5 kbps[1]。按 32 bit 纯字长计算，本仿真得到：

标称速率 32 位字纯传输时长 适用安全结论
100 kbps 0.32 ms 连续发送会快速消耗发送侧和接收侧时序预算
12.5 kbps 2.56 ms 同一字占线时间为高速的 8 倍，可扩大阻塞窗口

实际线路还涉及字间间隔、时钟容差、接收器同步和电气波形，不能用上述纯字时长替代设备实测。速率配置应视为通道资产：配置为 100 kbps 的接收器收到 12.5 kbps 发送时，通常会失去有效字同步或把采样解释为无效；具体容差需要在目标 LRU 上验证。

3. 原生安全能力与缺口

安全属性 原生 32 位字是否提供 依据和判断
来源认证 否 字中没有密码学来源字段；SDI 是配置语义，可复制[1]
消息完整性 部分 奇校验能发现部分比特错误；不能阻止有意篡改并重算奇偶
防重放 否 没有原生序号、时间戳、随机数或确认状态
语义约束 否（协议不负责） 标签确定解释方式；物理范围、变化率和交叉校验属于 ICD/系统逻辑
保密性 否 数据字段可由接触总线的观察者直接解析
发送侧访问控制 否 单发射端是架构约束，不是协议级身份授权
速率/占线保护 否 速率有配置模式，但没有安全限速、仲裁或可信发射配额

这组结论不是说所有接收机都“裸奔”：工程实现可能额外配置标签白名单、冗余源比较、范围检查、超时和告警。它们属于 LRU、ICD 或系统架构的附加控制，不应被误写成 ARINC 429 原生安全属性。

4. 攻击面与脆弱性条目

4.1 AR-01：缺少来源认证导致合法格式的伪造字被接收

协议层级： ARINC 429 字接收/标签解释层。
触发条件： 攻击者在目标通道的发送侧写入一个标签、SDI、数据和 SSM 均满足接收配置，且第 32 位奇偶校验正确的 32 位字；接收端没有独立的来源认证或通道外的可信源绑定。
适配设备： 消费该标签的 ARINC 429 接收 LRU；在典型机载应用中可能包括 ADC 数据消费者、惯导/姿态数据消费者、FMS/显示/自动飞行相关计算单元，实际适配性必须看具体 ICD。
利用前提： T1/T2/T3 至少获得一个能驱动目标通道的物理/逻辑入口；本条不成立于“只有远程客舱网络权限、没有总线桥接路径”的假设。
攻击路径： 被攻陷发射 LRU 或维护测试边界 → 目标 ARINC 429 TX 侧/桥接器 → 目标 RX 通道 → 接收 LRU 按标签白名单接收。
具体影响： 接收 LRU 看到的是“合法标签 + 合法奇偶”的数据，无法仅靠原生字区分合法源和伪造源。若该标签参与关键飞行参数计算，可能造成错误计算、错误告警、源切换或错误降级；是否能影响飞行控制必须由真实消费者和安全分析证明。
危害分级：高。 在标签进入关键计算且注入路径可在飞行中使用时，后果可能向极高升级；当前仿真没有证明具体飞机的失控后果，因此不直接给出极高结论。
仿真证据： 合成标签 0o203、数据 400000 的帧在 LegacyReceiver 中结果为 accepted；同一帧进入安全网关因 unauthorized_source 被拒绝。
来源： [1]（字段/传输方式）；[2][3]（航空网络安全风险识别和保护方法）；[E1]（本项目复现实验）。

整改： 在不可信输入进入安全相关消费者之前设置单一受控入口；绑定通道 ID、来源 ID、标签、序号和 MAC；受控出口只允许网关作为发送源。SDI、标签白名单和物理连接器不能单独作为来源认证。

4.2 AR-02：没有新鲜度状态导致捕获字可重放

协议层级： 消息时序/状态层。
触发条件： 攻击者先被动捕获一帧有效字，再在稍后把完全相同的字发送到同一标签消费者；接收端没有序号、时间窗或单调状态。
适配设备： 任何把周期性 ADC、惯导、系统状态或离散量标签当作当前值使用的接收单元。周期性数据尤其容易被“旧值看起来格式正常”掩盖。
利用前提： T4 能读取线路，且 T1/T2/T3 之一随后能把捕获字送回目标通道；如果只有被动读取而无发射能力，本条仅产生信息泄露，不产生重放。
攻击路径： 线束/接收侧被动探测 → 保存 raw_word → 进入发射/桥接侧 → 原样发往目标 RX → 旧值被当作当前值。
具体影响： 接收端可能继续使用陈旧的有效数值，直到应用层超时或冗余比较发现异常。结果包括错误状态保持、源切换延迟、告警延迟和计算偏差；实际后果由数据更新周期、监控门限和系统冗余决定。
危害分级：高（关键标签条件性）。 非关键状态标签可能只有中级运行影响；关键飞行输入的陈旧值可能导致更高安全后果。
仿真证据： 捕获字为 0x000fa083。原生接收端在后移时间、改变 source 后仍接受；安全网关首次接受序号 1，立即重复时返回 replay，在 500 ms 送达时返回 stale。
来源： [1]（原生字字段）；[3][4]（新鲜度、持续适航和监测方法）；[E1]。

整改： 网关按“来源 + 标签 + SDI + 通道”维护单调序号，结合受控时间窗；处理重启、掉电、序号回绕、双通道切换和维护模式，不能只在内存中简单保存一个计数器。对关键周期数据还应保留接收超时、更新率和冗余源一致性检查。

4.3 AR-03：奇偶校验不是抗篡改认证

协议层级： 字级传输错误检测层。
触发条件： 攻击者修改数据字段后重新计算奇偶位，或同时改变偶数个比特；生成的字仍满足奇校验。
适配设备： 采用标准奇偶校验检查、但没有外部 MAC/签名或应用层交叉校验的接收 LRU。
利用前提： 具备发送侧写入能力，或者能在桥接器中修改字；不需要破解任何密钥，因为原生字没有密钥。
攻击路径： 捕获/生成有效字 → 修改 Data/SSM → 重算 bit 32 → 发送 → RX 通过 parity check。
具体影响： 传输错误检测会给出“无错误”结果，篡改值进入后续范围和控制逻辑；即使某些接收器对状态变化做了检查，也不能把奇偶位当作真实性证据。
危害分级：高（关键数据条件性）。 若只对非关键维护数据使用，则可降为中；若影响关键输入，需按其安全后果评估。
仿真证据： 1000 修改为 2000 并重新编码，parity_ok=True；原生接收端接受，带原 MAC 的网关因 authentication 拒绝。单比特翻转基线被原生 parity 拒绝，两个比特翻转则仍可保持奇校验，说明检测能力与认证能力不同。
来源： [1]（奇校验）；[3]（完整性保护方法）；[E1]。

整改： 保留奇偶校验作为线路错误检测，同时在安全终止点对原生字、来源、通道、序号和时间戳计算认证标签。不要通过“增加奇偶检查次数”替代密码学完整性保护；密码算法、密钥长度、硬件加速和失效策略需进入项目安全架构与适航审查。

4.4 AR-04：标签语法有效但物理语义越界

协议层级： 标签解释和应用数据有效性层。
触发条件： 字的 Label、SDI、SSM 和 parity 都有效，但 Data 超出该机型 ICD 对该标签规定的物理范围，或虽在范围内但违反最大变化率、更新周期、冗余源一致性或状态转换约束。
适配设备： 将标签数据直接送入计算而没有完整语义验证的 ADC 消费者、显示/告警计算单元、FMS 或自动飞行相关消费者。真实适配对象以 ICD 为准。
利用前提： 攻击者可以发送任意有效格式字；目标接收端缺少范围/变化率/交叉源策略。
攻击路径： 选择已有合法标签 → 编码越界 Data 或不合理 SSM → 重算 parity → 发往消费者 → 应用层当作正常数值。
具体影响： 造成错误显示、告警、计算输入或触发非预期降级；如果应用层有饱和、限幅和独立源校验，后果可能被限制。
危害分级：高（接入关键计算时）；非关键维护标签可评为中。
仿真证据： 为避免冒充真实机型定义，实验标签 0o203 明确是合成标签；策略规定数据 0..10000，值 10001 原生端接受，网关返回 semantic_range。这证明的是“格式层与项目语义层分离”，不是 0o203 的真实物理范围。
来源： [1]（标签/数据字定义）；机型 ICD/标签分配表（真实落地时的主依据）；[3][5][6]（系统安全和安全评估接口）；[E1]。

整改： 由 ICD 生成可审计的标签策略：数据编码、合法范围、变化率、更新周期、SSM 合法转移、冗余源交叉比较和超时动作；异常时采取经安全分析确定的拒绝、冻结、切换备用或告警，不在通用网关中擅自定义飞控限值。

4.5 AR-05：连续发送导致总线占用和时延扩散

协议层级： 物理链路可用性与发送调度层。
触发条件： 已获得发送能力的攻击者连续排队发送合法奇偶字；目标接收通道在该时段无法对原生发送流做协议级仲裁。
适配设备： 共享一个接收通道的 ARINC 429 接收 LRU；特别是依赖周期更新和超时门限的计算单元。注意，典型架构要求单一发射端，因此攻击前提通常是发射 LRU 被攻陷、发射侧被替换、或桥接/维护边界失去单发射端约束，而不是简单把第二个发射器并联到线上。
攻击路径： 受损发射端/桥接器 → 连续合法格式字 → RX 输入队列/线路 → 合法周期字等待或丢失 → 超时/降级。
具体影响： 产生输入时延、更新丢失、告警或备用源切换；若持续占用且无独立故障遏制，可能扩大到多个消费者。
危害分级：高（时间关键标签条件性）。 若目标消费者具备快速失效检测和独立冗余，可能为中；需要真实时间预算确认。
仿真证据： 在 100 kbps、64 个攻击字均从 t=0 排队时，每字纯传输 0.32 ms，合法字从 20.48 ms 才开始；设定 5 ms 期限则超时。受控网关拒绝全部 64 个未认证攻击帧，合法帧从 0 ms 开始。12.5 kbps 时同一 64 字队列的理论阻塞为 163.84 ms，进一步说明低速通道的时序预算更紧；该数字不含字间隔。
来源： [1]（单向通道和速率）；[3][5][6]（可用性与安全/安全评估）；[E1]。

整改： 用物理单发射端约束、端口/连接器控制、发送授权、总线占用监测和故障隔离共同处理。网关入口限速只能保护“网关之前”的受控路径；若攻击者能直接绕到网关输出侧，必须依靠物理隔离、bus guardian/发送使能控制、冗余链路和接收侧超时/降级。所有新控制都要做故障模式与误拒绝分析。

4.6 AR-06：100 kbps/12.5 kbps 配置失配导致有效数据不可用

协议层级： 物理时序/接口配置层。
触发条件： 接收端按 100 kbps 配置，发送端按 12.5 kbps 发送，或反之；两者相差 8 倍，超出本仿真使用的 2% 锁定容差。
适配设备： 维护更换后的 LRU、错误装载配置的总线接口卡、测试适配器和被桥接的双速率通道。
利用前提： 攻击者能改变发送端速率选择或插入可配置测试发射器；配置错误也可能由维护过程造成。
攻击路径： 维护/配置边界 → 修改速率模式 → TX 与 RX 时钟不匹配 → 接收端无法形成有效 32 位字 → 数据丢失/超时。
具体影响： 主要是可用性损失、超时和备用源切换；不同 LRU 的同步/容差实现可能产生不同表现，不能据仿真统一断言为“必然静默”。
危害分级：中。 若影响单一非关键功能通常为中或低；若同时切断关键输入，应按真实失效后果升级。
仿真证据： 接收配置 100000 bit/s、发送 12500 bit/s 时，纯字时长分别为 0.32 ms 和 2.56 ms，receiver_valid_word=False；同速率配置均锁定。
来源： [1]（双速率及字传输）；机型接口配置文件；[E1]。本条的具体容差仍需目标 LRU 台架验证。

整改： 速率作为不可由普通维护会话任意改变的端口配置；启用上电自检、配置签名/版本核对、实际比特定时监测和失配告警；在地面测试程序中覆盖两种标称速率与错误配置，不用软件层 MAC 代替硬件端口控制。

4.7 AR-07：明文可观测，捕获内容可辅助后续攻击

协议层级： 线路保密性和维护信息保护层。
触发条件： 攻击者可以在接收端、线束或连接器处被动读取；ARINC 429 字中的标签、数据、SSM 和 parity 可直接解析。
适配设备： 传递飞行参数、设备状态、维护状态或配置相关信息的通道。信息敏感度取决于具体 ICD。
利用前提： T4 的物理接触或合法接收路径观测能力；仅被动观测不等于能够注入。
攻击路径： 线束/测试端口被动探测 → 解析标签和数据 → 建立更新周期和状态模型 → 为重放或社会工程/维护攻击提供素材。
具体影响： 单独看通常是信息泄露和攻击准备，不直接证明飞行控制后果；若数据具有运行或维护敏感性，可能提高后续攻击成功率。
危害分级：低（本条单独的安全后果）。 与主动重放组合时，按 AR-02 重新评估，不重复计分。
仿真证据： 合法字 0x000fa083 可解析为合成标签 0o203、数据 1000；native_confidentiality=False。
来源： [1]（字字段）；[2][3][4]（信息安全过程与持续适航）；[E1]。

整改： 优先物理保护线束、连接器和测试端口；在需要保密的跨域边界采用经项目批准的加密/安全封装，并在安全网关终止，不擅自改写原生 32 位接收端协议。需要同时评估延迟、密钥可用性、失效降级和维护可诊断性。

5.3 实验步骤与结果

E-01：奇偶校验基线

  1. 编码合成标签 0o203、数据 1000。
  2. 单独翻转一个数据位：原生接收端结果为 parity 拒绝。
  3. 修改数据并重新计算奇偶：奇偶仍有效，原生接收端接受。
  4. 同时翻转两个数据位：奇校验仍可能有效，说明奇偶校验不能覆盖偶数位错误。

结果： 奇偶校验可以作为线路传输错误检测，但不能作为抗恶意篡改的认证机制。

E-02：未授权来源注入

  1. 生成标签正确、奇偶正确、数据为 400000 的帧。
  2. 将来源设置为 attacker。
  3. 分别送入 LegacyReceiver 和 SecureGateway。

结果： 原生端 accepted=True；网关 accepted=False, reason=unauthorized_source。

E-03：捕获和重放

  1. 生成原始字 0x000fa083。
  2. 原生端在后移时间并改变来源后重发，仍按格式接受。
  3. 给安全帧附加序号 1 和时间戳 0，先在 t=0 送达，再在 t=20 ms 原样重发，最后在 t=500 ms 送达。

结果： 原生端接受；网关首次接受，第二次以 replay 拒绝，新的网关在 500 ms 以 stale 拒绝。

E-04：重算奇偶后的数据篡改

  1. 把数据 1000 改为 2000。
  2. 重新生成原生字和奇偶位。
  3. 对安全帧只替换 raw_word，保留旧 MAC。

结果： 原生端接受且 parity_ok=True；网关以 authentication 拒绝。

E-05：语义范围检查

  1. 对合成标签配置策略 0..10000。
  2. 发送数据 10001 的格式合法帧。

结果： 原生端接受；网关以 semantic_range 拒绝。该测试不宣称真实标签 0o203 的物理范围。

E-06：连续占线

  1. 在 t=0 排队 64 个攻击帧，再排队一个合法帧。
  2. 使用 100 kbps 计算纯字串行化。
  3. 将合法帧截止时间设为 5 ms，比较其开始发送时间。

结果： 原生队列中 64 个攻击帧均被接受，合法帧从 20.48 ms 开始，超过 5 ms；安全网关拒绝全部攻击帧，合法帧从 0 ms 开始。该结果是“攻击者已取得发送侧能力”的时序证据，不是对任意并联发射器电气可行性的证明。

E-07：速率失配

  1. 接收端配置 100 kbps，发送端配置 12.5 kbps。
  2. 按 32 bit 纯字时长计算并调用 timing_lock。

结果： 0.32 ms 对 2.56 ms，接收端有效字判定为 False。该模型用于证明失配的攻击/故障触发条件；具体 LRU 的同步捕获、容差、告警和备用源动作必须在硬件台架复测。

5.4 证据效力边界

本实验可以证明：在给定抽象接收规则下，原生字段不足以区分若干恶意输入，而网关策略可以拒绝这些输入。它不能证明：

  • 某个真实机型采用 0o203，或该标签直接连接某个飞控/发动机控制功能；
  • 任意线束都能被无损插入或任意第二发射器都能与原发射器并联工作；
  • 具体 LRU 的电压、端接、波形、EMI、容错和故障隔离行为；
  • 某种密码算法已满足该型号的适航审定基础。

6. 风险分级与整改后残余风险

6.1 本报告采用的四级规则

按赛题指定的“极高、高、中、低”四级，本报告使用以下判定口径。等级是当前架构假设下的安全风险初判，最终等级要和功能危害分析、系统安全性评估、暴露条件及飞行阶段结合。

等级 判定口径
极高 具有可信的在役/飞行中攻击路径，能够直接或级联造成灾难性飞行安全后果，且没有有效独立遏制/检测
高 可影响安全相关数据的真实性、时效或可用性，可能导致错误计算、危险降级或关键时序违约；路径或后果仍有条件约束
中 主要造成可检测的局部功能、维护或运行影响，或需要地面维护/特殊接触条件；存在独立冗余或安全降级
低 信息泄露、非关键数据异常或已被快速检测且不改变安全功能；仍需记录并防止与其他路径组合放大

7.3 受控安全帧的实验定义

本实验使用如下外部封装，便于验证控制链：

source | timestamp_ms | sequence | native_raw_word | HMAC-SHA-256 tag

这不是 ARINC 429 原生字的新格式。安全网关验证后才把 native_raw_word 输出到原生接收侧。代码中的密钥 arinc429-lab-secret 是单一合成来源的固定测试密钥，只为确定性实验；多来源装机不能共享该密钥，应使用每源独立密钥或经批准的密钥派生。实际系统应由安全架构确定算法、密钥层级、硬件保护、更新和失效策略，并完成独立验证。

9. 适航与持续适航落地

  1. 以机型功能架构、ICD、标签分配表和数据流图建立资产清单；每个标签绑定消费者、更新周期、范围、冗余和故障动作。
  2. 按 DO-326A/ED-202A 建立航空器系统信息安全过程：资产/威胁、脆弱性、风险、保护目标、验证证据和变更控制闭环[2]。
  3. 按 DO-356A/ED-203A 选择与验证安全方法；本报告提出的认证网关、物理隔离、监测和反重放应转化为系统安全需求，而不是停留在“建议使用加密”[3]。
  4. 对维护和在役变化按 DO-355/ED-204A 纳入持续适航：密钥撤销、GSE 版本、配置装载、事件日志、漏洞情报和异常报告[4]。
  5. 用 ARP4754A、ARP4761A 及适用的机型安全评估流程分析错误数据、数据丢失和时延对功能的传播；DO-178C/DO-254 等软件/硬件保证活动是否适用，由项目审定基础决定[5][6]。
  6. 向民航适航规章的设备系统安全要求映射时，应使用项目实际适用的 CCAR/局方审定基础；例如运输类飞机设备系统安全性不能仅以“实验脚本通过”替代适航符合性判断[7]。

本次运行使用 JSBSim 自带的 737/cruise_init.xml 研究初始条件，并执行 JSBSim 纵向配平以去除启动瞬态；外部采样周期为 1000 ms，内部积分步长按 JSBSim 模型的 8.33 ms 设置。正常流共输出 124 个合成 ARINC 429 帧，安全网关接受 124 个，拒绝 0 个。攻击时选择合成高度标签 0o203，构造奇偶有效但来源为 attacker 的数据字：简化原生接收端 accepted=True，受控网关 accepted=False, reason=unauthorized_source。

这证明的是“飞行动力学状态能够进入本项目的航电安全验证链，并且攻击判定仍然有效”，不证明 737/A320 真实设备使用本实验标签，也不证明任何具体飞行控制功能可被该字直接影响。

11. 结论

ARINC 429 原生机制适合定义和传输机载数据，但奇偶校验、标签、SDI 和 SSM 不提供密码学来源认证、抗重放、保密性或安全调度。通过本地仿真可以复现具体、可观察的边界：格式正确的未授权帧、重放帧、重算奇偶篡改帧和语义越界帧均可被简化原生接收端接受；增加受控安全入口后，来源、MAC、新鲜度、语义和入口限速控制分别拒绝对应输入。

整改不能只加一个软件过滤器。民用航空可落地的方案必须把物理单发射端约束、维护/GSE 隔离、网关认证、反重放、ICD 语义策略、占用监测、速率锁定、密钥生命周期和安全/适航验证组合起来。当前结果足以作为协议层风险证明和加固方案的逻辑回归证据；要形成型号级结论，还需补充真实 LRU/ICD、目标标签安全评估、硬件波形/EMI、旁路路径、故障隔离和适航过程证据。
