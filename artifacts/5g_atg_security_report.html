作答场景： 民用航空5G地空宽带通信全链路，包括机载5G终端、地空基站、专属核心网、地面应用系统，以及客舱网络、机载航电和地面运维之间的边界

报告版本： 1.0

验证日期： 2026-08-24

危害分级： 极高、高、中、低四级。分级针对本报告定义的民航业务和边界，不能替代具体机型的 FHA、SSA、网络安全评估或适航审定结论。

结论性质： 本报告的攻击证据来自本地数字状态模型和合成项目 ICD，不是实际射频发射、真实伪基站、真实gNB/5GC、真实SIM/eSIM、真实飞机或运行系统测试。

摘要

5G-ATG不是一个脱离3GPP 5GS/NR体系、所有运营方都采用同一实现的独立协议。本报告将它建模为面向民航航空地空宽带业务的5GS/NR部署profile：机载5G UE通过Uu接入ATG地空gNB，经N2/N3进入AMF/SMF/UPF专属核心网，再由N6连接地面应用系统。atg.cabin、atg.maint、atg.avionics、S-NSSAI、QFI和TEID均作为合成的项目接口控制数据，用于验证隔离和安全状态，不代表任何运营商或机型的实际配置。

结论不是“5G天然不安全”。3GPP 5GS已经定义了5G-AKA、NAS/RRC安全、用户面保护和网络功能安全机制，但这些机制在空口广播、初始接入、N3/N6传输、应用接口、切片路由、OAM配置和客舱/航电边界之间并不会自动形成端到端安全闭环。专属核心网的物理隔离也不能替代逻辑认证、最小权限和跨域策略。

2. 协议原理与原生安全边界

2.1 5G-ATG与公网5G的关系（结论：C-N-01）

5G-ATG的差异主要来自民航业务、空地覆盖、频率和部署profile，而不是另有一套统一的“ATG安全协议”。基础协议仍应在项目采用的3GPP 5GS/NR版本范围内确认：TS 23.501描述5GS架构和参考点，TS 23.502描述注册、PDU会话、移动性等流程，TS 24.501描述5GS NAS，TS 38.300/38.331描述NR/NG-RAN和RRC，TS 33.501描述5G安全架构与过程。[1]-[6]

因此相对公网5G，专属民航部署的重点差异和风险是：

  • 网元专属化： 专属AMF/SMF/UPF和地面应用物理隔离公网，降低共享基础设施暴露，但如果OAM跳板、供应商维护链路或N6出口被信任地桥接，物理隔离不会自动形成逻辑授权；
  • 业务专用化： DNN、S-NSSAI和QFI按客舱、机务、航电业务划分，减少业务混合，但DNN/切片配置错误可能把错误业务映射到错误UPF或错误地面应用；
  • 空中覆盖和移动性： 高空长距离覆盖、跨地面站切换和三维航迹使小区选择、邻区、切换、状态同步和链路丢失处理成为民航特有关注点；
  • 定制和运维： 专用频率、定制空口参数、供应商专用网元和机载固件会减少通用公网生态的自动升级能力，补丁、配置、证书和回滚流程成为高价值控制点；
  • 业务后果更集中： 客舱宽带中断主要影响旅客服务，机务回传错误影响持续适航和放行判断，而任何通向航电控制或安全关键显示的数据路径都必须独立隔离、鉴权和验证。

2.3 注册和安全建立顺序（结论：C-N-02、C-N-03）

在抽象流程中，UE先选择可见小区并接收系统信息，随后建立RRC连接、发送初始NAS注册请求，完成5G-AKA和安全模式，再建立PDU会话。广播、部分小区信息和初始接入元数据处在完整安全上下文之前；这解释了为什么加固UE可以拒绝未信任小区，却不能让外部观察者看不见所有广播和初始交互。[2]-[6]

5G-AKA和NAS/RRC安全建立后，真实系统的算法选择、完整性和加密开关、用户面保护、密钥派生、重建和切换处理都必须按TS 33.501及项目安全配置核验。报告不能把“使用5G”简化成“任何Uu、N3、N6和应用消息都天然端到端加密”。

2.4 N3、DNN、切片、QFI和TEID的安全边界（结论：C-N-04）

GTP-U由TS 29.281定义承载格式和隧道语义；PFCP/N4由TS 29.244定义会话规则和UPF控制。TEID是隧道标识，QFI是QoS Flow标识，DNN和S-NSSAI用于业务选择与切片/会话上下文。它们必须与UE、PDU会话、N3对端、来源安全域和应用授权绑定，但不能单独证明“这条消息来自合法航电设备”。

本项目加固网关的判定顺序是：活动PDU会话 -> TEID和S-NSSAI -> QFI -> 来源安全域 -> 客舱/航电跨域策略 -> 应用TLS要求 -> 来源HMAC -> 时间戳 -> 序号 -> 业务字段范围 -> 入口限速。该顺序用于展示分层控制；真实系统应由经过批准的安全架构和实现完成，不能直接复制合成HMAC接口。

3. 架构差异脆弱性

3.1 AD-01：专属核心网物理隔离被误当成逻辑隔离（结论：C-AD-01）

  • 协议/接口层级： 5GS部署架构、N2/N3/N6和OAM/OSS管理平面；对应TS 23.501参考点和TS 29.281/29.244会话转发语义。
  • 触发条件： 专属AMF/SMF/UPF与公网物理隔离，但供应商维护跳板、运营OAM、N6路由或跨域代理被配置为可信桥接；缺少按身份、角色、DNN、S-NSSAI和目标安全域的显式授权。
  • 适配设备： 专属核心网网元、地面路由器、UPF、OAM服务器、供应商跳板、机载5G数据适配器和客舱/航电边界网关。
  • 利用前提： 攻击者先获得维护跳板、管理账号、被攻陷网元或错误配置的跨域路由；本报告不假定公网用户可以直接穿透物理隔离。
  • 攻击路径： 维护入口或内部桥接器 -> OAM/N6配置 -> UPF转发规则或边界ACL -> 客舱业务到航电/维护目标的错误路径。
  • 具体业务影响： 物理隔离仍在，但逻辑路由可能把客舱宽带或维护流量送到不应到达的应用和航电安全域，形成跨域注入、数据泄露或维护操作越权。
  • 危害分级： 极高。本级别只适用于该错误路径确实能够到达安全关键航电功能的项目；若经过只读监视代理且不能输出控制命令，应按实际功能降级。
  • 验证思路： 在隔离台架建立合成DNN/S-NSSAI和UPF规则，分别提交未授权OAM路由变更、客舱命令和合法航电遥测，检查路由、应用消费和审计记录。
  • 仿真证据： attacks.oam_route_change.native.accepted=True，未授权加固请求返回oam_rbac；attacks.cabin_to_avionics_boundary.native.accepted=True，加固网关返回cabin_to_avionics_boundary。证据文件见artifacts/5g_atg_results.json。
  • 整改措施： 将物理隔离和逻辑隔离作为两个独立控制；边界默认拒绝；客舱到航电只允许明确的只读字段或经过安全代理的单向数据；OAM使用独立管理面、mTLS、RBAC、双人审批、签名配置、不可篡改审计和回滚；以真实ICD和安全域定义验证所有N6及机载路由。
  • 来源： [1] TS 23.501的5GS架构和参考点；[8] TS 29.244的UPF会话规则；[9]-[11] DO-326A、DO-356A、DO-355；[14] CCAR-25 §25.1309。

3.2 AD-02：专用DNN、切片和UPF路由的配置差异风险（结论：C-AD-02）

  • 协议/接口层级： 5GS DNN、S-NSSAI、PDU会话、N4/PFCP和N6路由；对应TS 23.501切片/DNN/QoS架构、TS 23.502 PDU会话流程、TS 29.244。
  • 触发条件： atg.cabin、atg.maint和atg.avionics共用UPF或转发策略，但未执行DNN-S-NSSAI-UE-应用的绑定校验；TEID/QFI被当作可信来源字段。
  • 适配设备： 机载UE profile、AMF/SMF、UPF、PCF、N4控制链路、N6防火墙和地面应用接入网关。
  • 利用前提： 需要恶意或错误的PDU会话参数、被攻陷的UPF/桥接器或可修改的PFCP/OAM配置；不能仅凭知道DNN名称绕过真实5G-AKA。
  • 攻击路径： 伪造/错配PDU会话状态 -> 使用合法格式的GTP-U业务包 -> UPF按错误TEID或QFI转发 -> 另一DNN或地面应用消费。
  • 具体业务影响： 客舱数据可能进入机务或航电接收端；机务记录可能进入错误飞机或错误航班；QoS误配可能使遥测、维护和客舱流量争用带宽。
  • 危害分级： 高；一旦跨入安全关键航电输出路径，按AD-01条件升级为极高。
  • 验证思路： 为每个PDU会话记录UE、Cell、DNN、S-NSSAI、TEID、QFI、N3对端和目标应用，逐一改变一个字段，确认错误字段在UPF/安全网关被拒绝且没有应用副作用。
  • 仿真证据： TEID伪造返回session_binding，QFI伪造返回qfi_binding；弱化路由均接受并转发到合成地面应用。
  • 整改措施： 建立配置生成器和静态检查；每条规则绑定完整PDU会话和安全域；拒绝未注册DNN、未知S-NSSAI、TEID/QFI不匹配、来源区改变和N3端点改变；对N4/PFCP和OAM配置做完整性保护、双人复核、变更回放和负向测试。
  • 来源： [1] TS 23.501；[2] TS 23.502；[7] TS 29.281；[8] TS 29.244；[10] DO-356A。

3.3 AD-03：高空大覆盖和高速移动性带来的状态连续性风险（结论：C-AD-03）

  • 协议/接口层级： NR小区选择、RRC连接、NG-RAN移动性、N2/Xn切换、NAS安全上下文、PDU会话和N3隧道；对应TS 23.502、TS 38.300和TS 38.331。
  • 触发条件： 飞机快速跨越地空小区覆盖区、邻区重叠或链路质量快速变化，切换上下文、密钥、QoS和TEID更新存在延迟、回滚或配置不一致。
  • 适配设备： 机载UE、ATG gNB邻区配置、AMF/SMF/UPF、地面传输网络和应用接收缓冲区。
  • 利用前提： 需要真实或仿真的移动性状态、可控的邻区/链路条件或错误的gNB切换配置；本项目当前只完成注册状态，未声称已复现真实切换缺陷。
  • 攻击路径： 构造覆盖边缘/丢包/重复切换条件 -> 触发旧小区和新小区状态交叠 -> 旧TEID或旧序号包被错误接受，或合法业务长时间中断 -> 地面应用使用陈旧状态。
  • 具体业务影响： 客舱宽带和机务回传间歇中断；遥测时间顺序错误；重复维护记录；切换期间的安全降级、重新注册或恢复策略失效。
  • 危害分级： 高；如果业务路径被证明影响安全关键数据，应结合独立备用源和时间预算重新评估。
  • 验证思路： 扩展状态模型或真实授权台架，按航迹时间序列注入切换、重复、延迟和旧上下文包，核对安全上下文、TEID、序号、时间戳和应用状态是否原子更新。
  • 仿真证据： 当前证据覆盖注册超时、初始安全状态和会话绑定；切换/飞行航迹验证标记为“待扩展验证”，不得写成已测试结果。
  • 整改措施： 对切换前后上下文设置明确生效边界和旧状态失效时间；应用层使用单调序号和时间窗；地面应用按飞机、航班、会话和时间戳去重；设计链路丢失时的安全降级和恢复，不能以静默重连替代安全状态确认。
  • 来源： [2] TS 23.502移动性和PDU会话流程；[5] TS 38.300；[6] TS 38.331；[9]-[11]民航航空器网络安全方法和持续适航指导。

3.4 AD-04：专用部署和运维节奏造成的补丁、证书和配置风险（结论：C-AD-04）

  • 协议/接口层级： gNB/5GC网元固件、OAM管理接口、证书/密钥管理、配置发布和回滚流程；具体OAM协议依供应商ICD冻结，不能泛化为某一种REST、NETCONF或CLI缺陷。
  • 触发条件： 专属网络不能像公网共享平台一样自动更新；网元版本、UE固件、信任锚、切片策略和地面应用版本由不同组织维护，存在版本漂移、过期证书、临时调试账号或未验证回滚配置。
  • 适配设备： 机载UE、ATG gNB、AMF/SMF/UPF、OAM/OSS、供应商跳板、证书服务器和地面应用。
  • 利用前提： 需要维护窗口、供应商账号、被篡改的升级包、错误信任锚或配置发布权限；本报告不指向某个厂商的具体CVE。
  • 攻击路径： 供应链/维护介质/跳板 -> 网元或UE配置/固件 -> 安全策略降级、跨域路由打开或日志失效 -> 业务流量进入错误边界。
  • 具体业务影响： 空地链路无法注册；证书验证失败；专属切片隔离失效；维护数据被错误接收；故障追溯和持续适航记录不完整。
  • 危害分级： 高；若升级包或配置能关闭航电边界控制，按极高处理。
  • 验证思路： 建立版本、证书、配置基线；在断网台架验证签名、回滚、过期证书、角色变更和审计；用合成OAM请求验证未经授权的配置不会生效。
  • 仿真证据： OAM弱化模型接受未授权路由变更；加固模型要求RBAC、mTLS、双人审批、HMAC、序号和受保护边界策略。
  • 整改措施： 固件和配置签名；硬件保护的密钥和信任锚；最小权限和临时授权；供应商账号隔离；版本互操作矩阵；变更前后自动化负向测试；安全审计和可回滚基线。
  • 来源： [9] DO-326A/ED-202A；[10] DO-356A/ED-203A；[11] DO-355/ED-204A；[12] SAE ARP4754A；[14] CCAR-25 §25.1309。

4. 全链路脆弱性深度分析

4.1 F-01：Uu广播和初始安全上下文完成前的恶意小区诱捕（结论：C-F-01）

  • 协议/接口层级： NR系统信息广播、RRC连接建立、初始NAS注册和5G-AKA/安全模式建立；对应TS 38.331、TS 24.501和TS 33.501。
  • 触发条件： UE在可见范围内发现具有相同或相似PLMN/ATG能力标识的未信任小区；UE的网络信任校验、运营商白名单、降级策略或告警策略不严格。
  • 适配设备： 机载5G UE、ATG gNB、机载天线/射频前端和地面小区规划；实验中的设备名为合成ROGUE-GNB-01。
  • 利用前提： 现实攻击需要经授权频谱和安全实验环境验证的射频覆盖或信号条件；本实验只提供数字广播可见、初始注册可见和AKA失败状态。
  • 攻击路径： 可见SIB/小区参数 -> UE选择小区 -> RRC setup -> 初始NAS Registration Request元数据暴露 -> 5G-AKA或网络信任校验失败；弱化策略可能先驻留后拒绝业务。
  • 具体业务影响： 机载终端身份/能力/业务元数据暴露；合法小区被诱导离开造成业务中断；维护终端可能进入错误接入状态。真实5G-AKA未被绕过时，不能宣称攻击者获得用户面密钥或真实IMSI/SUPI。
  • 危害分级： 高。若存在允许未认证网络承载敏感业务、明文降级或可到达航电边界的例外路径，应升级为极高。
  • 验证思路： 在射频屏蔽或纯数字状态台架中配置可信/未信任小区，记录SIB可见、RRC setup、初始NAS、AKA结果、安全模式和用户面状态；检查加固UE是否拒绝驻留并告警。
  • 仿真证据： rogue_cell_hardened.result=rogue_cell_rejected，rogue_cell_legacy.result=camped_untrusted_cell；两者pre_security_metadata_visible=True，两者user_plane_ready=False。
  • 整改措施： 严格校验运营商PLMN、TAC、ATG能力和授权邻区；禁止不受控安全降级；在安全上下文建立前只发送协议必需的最小信息；UE保存并保护信任锚和网络策略；对AKA失败、异常小区选择和重复注册告警；不以“隐藏广播”代替认证。
  • 来源： [6] TS 38.331关于NR系统信息和RRC；[3] TS 24.501关于NAS注册；[4] TS 33.501关于5G-AKA和接入安全；[10] DO-356A。

4.2 F-02：Uu信号干扰造成注册、切换和业务不可用（结论：C-F-02）

  • 协议/接口层级： NR物理层/链路层可用性、RRC连接、NAS注册和PDU会话建立；对应TS 38.300、TS 38.331和TS 23.502。
  • 触发条件： UE无法稳定接收同步、系统信息或RRC/NAS消息，或者上下行丢包超过重传和超时窗口。
  • 适配设备： 机载UE、ATG gNB、地面站覆盖区、机载天线和无线资源管理组件。
  • 利用前提： 现实验证需要频谱授权、射频屏蔽、EMC/EMI安全流程和批准的干扰模拟器；本实验将其抽象为RRC/NAS丢失，不产生RF。
  • 攻击路径： Uu消息丢失 -> RRC setup或NAS Registration Request无法完成 -> 5G-AKA/安全模式/PDU会话不发生 -> 客舱、机务和地面业务进入链路不可用状态。
  • 具体业务影响： 客舱宽带中断；机务数据回传延迟；运行监视缺少最新数据；若系统错误地把5G-ATG当作唯一安全关键数据源，可能使飞行运行和维护判断失去独立信息。
  • 危害分级： 高。存在经安全评估确认的独立备用链路和安全降级时，不应把可用性中断直接升级为飞机失控；无备用且影响安全关键功能时应重新评估为极高。
  • 验证思路： 在数字模型中改变RRC/NAS丢失状态，测量注册超时、业务恢复、告警和安全降级；在后续授权射频台架中再测覆盖边缘、频偏、多普勒、遮挡和干扰容限。
  • 仿真证据： attacks.interference.registration.result=registration_timeout，reason=uu_interference_or_signal_blocking，service_available=False。
  • 整改措施： 设计空地链路丢失检测、重连上限、告警和安全降级；客舱和机务业务分级恢复；航电数据不得依赖未验证的客舱承载；利用覆盖冗余、链路监测和频谱管理降低单点可用性风险；所有RF试验遵守批准的频谱和安全流程。
  • 来源： [2] TS 23.502；[5] TS 38.300；[6] TS 38.331；[11] DO-355；[14] CCAR-25 §25.1309。

4.3 F-03：NAS注册和PDU会话信令风暴（结论：C-F-03）

  • 协议/接口层级： NAS Registration、Service Request、PDU Session Establishment及N2控制面状态；对应TS 23.502、TS 24.501和TS 23.501。
  • 触发条件： 可见ATG小区允许大量请求进入AMF/SMF，认证前没有按源、UE、时间窗和航班/接入批次做资源保护，或者异常重试没有上限。
  • 适配设备： 机载UE、恶意或故障UE、ATG gNB、AMF、SMF、UDM/AUSF前置状态和地面接入控制器。
  • 利用前提： 需要能够向授权实验小区或数字接入边界提交注册/会话请求；本实验不生成真实NAS/GTP报文，只重复合成状态请求。
  • 攻击路径： 50次同一时刻注册请求 -> 弱化AMF模型逐次分配上下文 -> 状态表、计时器或认证链路压力增大；加固模型在每秒10次后拒绝后续40次。
  • 具体业务影响： 合法飞机注册延迟、切换和PDU会话建立失败；AMF/SMF资源被异常消耗；地面应用看见数据长时间缺失；如果与干扰同时发生，恢复风暴可能加剧不可用窗口。
  • 危害分级： 高。
  • 验证思路： 在隔离数字模型中固定时间戳，重复注册请求，分别记录上下文分配、拒绝原因、合法UE恢复时间和告警；用不同源、不同DNN和不同飞行阶段验证限速不误伤合法业务。
  • 仿真证据： attempts=50；弱化模型native_contexts_allocated=50；加固模型hardened_contexts_allocated=10、hardened_rejected=40、原因signaling_rate_limit。
  • 整改措施： 在gNB/AMF入口实施每源、每UE、每小区、每DNN和全局配额；把昂贵状态分配推迟到必要的认证和策略检查之后；设置异常重试上限、过载保护、优先级和白名单；保护合法在航UE的切换和恢复资源；将限速、丢弃、上下文数和恢复时延纳入监控与安全测试。
  • 来源： [2] TS 23.502；[3] TS 24.501；[1] TS 23.501；[10] DO-356A。

4.4 F-04：用户面报文篡改导致地面遥测和维护判断错误（结论：C-F-04）

  • 协议/接口层级： N3 GTP-U承载、N6应用消息和地面应用数据完整性；对应TS 29.281、TS 23.501和TS 33.501的用户面保护要求。
  • 触发条件： 业务从UPF到地面应用只依赖源地址、TEID或受信任传输，未对应用消息做端到端完整性校验，或安全网关允许未认证数据直接入库。
  • 适配设备： 机载航电数据适配器、UPF/N3传输、N6路由器、航班运行监视和机务数据接收应用。
  • 利用前提： 攻击者需要位于可修改数据的传输/桥接边界，或已经控制发送端、地面接入代理或网元；不能把“知道报文字段”当成获得合法密钥。
  • 攻击路径： 捕获合成AIRCRAFT_TELEMETRY -> 将高度从30000 ft改为500 ft、保留原始认证字段 -> 弱化路由直接交给地面应用；加固网关验证来源密钥和完整消息后拒绝。
  • 具体业务影响： 运行监视画面、告警判断、航班状态和机务数据记录出现错误；如果同一机制承载未经隔离的航电命令，可能转化为对航电功能的非授权输入。
  • 危害分级： 高。实际消息进入安全关键功能时应按该功能的安全目标升级为极高。
  • 验证思路： 先让合法遥测通过，再只修改一个字段，不修改原始HMAC/签名，比较原生和加固网关的应用状态；验证拒绝报文没有写入地面数据库和航电命令队列。
  • 仿真证据： data_tamper.native.accepted=True且效果为telemetry_updated:500ft；加固结果为accepted=False、reason=authentication。
  • 整改措施： 在N6业务入口采用经过项目批准的mTLS、消息认证码或数字签名；认证覆盖飞机、会话、DNN、S-NSSAI、QFI、TEID引用、消息类型、序号、时间戳和payload；实施模式校验、范围校验、异常隔离、审计和密钥轮换；地面应用不得仅信任源IP、GTP-U外层或VLAN。
  • 来源： [7] TS 29.281；[4] TS 33.501；[9]-[11] DO-326A、DO-356A、DO-355。

4.5 F-05：用户面重放造成陈旧遥测或重复维护操作（结论：C-F-05）

  • 协议/接口层级： N3/N6用户面消息、业务序号、时间戳和应用状态；GTP-U承载由TS 29.281定义，抗重放需要部署侧或应用侧状态。
  • 触发条件： 接收端只检查帧格式、DNN或传输完整性，不保存每飞机/每会话/每消息类型的最新序号和时间窗，或者切换后旧会话仍被接受。
  • 适配设备： 机载UE、UPF、N6网关、地面遥测数据库、机务工单/维护应用。
  • 利用前提： 攻击者先获得一条合法业务消息的副本，或者控制记录/转发设备；被动监听和主动注入需要不同物理或网络前提。
  • 攻击路径： 记录合法遥测或维护记录 -> 在稍后重复提交 -> 弱化路由再次消费；加固网关检查序号和时间窗，第二次提交返回replay。
  • 具体业务影响： 地面状态回退或重复；维护记录重复入库；旧配置/旧状态在错误时间被使用；切换恢复期间可能放大状态混乱。
  • 危害分级： 高。重复维护命令或安全关键输入的后果按目标功能重新评估。
  • 验证思路： 合法消息首次提交必须成功；相同消息立即再次提交、跨时间窗提交、切换后使用旧TEID提交，分别观察拒绝原因和应用状态是否保持不变。
  • 仿真证据： data_replay.native.accepted=True；加固网关第一次接受，第二次accepted=False、reason=replay。
  • 整改措施： 使用持久化单调序号、每会话和每消息类型的窗口、明确时间同步误差和切换状态；重启/回滚时保护序号状态；维护操作使用一次性授权、双人审批和业务幂等键；记录拒绝和异常时钟事件。
  • 来源： [2] TS 23.502移动性和会话流程；[4] TS 33.501安全过程；[7] TS 29.281；[10] DO-356A。

4.6 F-06：TEID、QFI、DNN和S-NSSAI未绑定造成会话/切片混淆（结论：C-F-06）

  • 协议/接口层级： N3 GTP-U、N4 PFCP、DNN、S-NSSAI和QoS Flow/QFI；对应TS 23.501、TS 29.244和TS 29.281。
  • 触发条件： UPF或地面接入网关仅根据一个外层标识转发，未同时核对UE、活动PDU会话、N3对端、DNN、S-NSSAI、TEID、QFI和来源安全域。
  • 适配设备： UPF、N3边界、N6安全网关、机载5G UE、客舱和航电数据适配器。
  • 利用前提： 需要能够构造或修改合成数据面元数据、控制错误转发设备或利用配置错误；真实GTP-U发送必须在授权实验网络内验证。
  • 攻击路径： 保留已知atg.cabin而修改TEID或QFI -> 弱化路由把包视为可信传输并交给地面应用 -> 加固网关按当前PDU会话拒绝。
  • 具体业务影响： 跨飞机、跨切片、跨DNN的数据混淆；客舱与机务数据错投；错误QoS造成关键遥测延迟；若路由继续向航电域，可能形成跨域输入。
  • 危害分级： 高；可到达航电控制路径时为极高。
  • 验证思路： 对合法包分别改变TEID、QFI、S-NSSAI、DNN、UE来源区和N3对端，要求每一项都有独立拒绝记录并且应用无副作用。
  • 仿真证据： TEID错误返回session_binding；QFI错误返回qfi_binding；弱化路由均返回accepted_trusted_transport。
  • 整改措施： UPF按完整PDU会话和N3对端维护短生命周期状态；严格校验DNN/S-NSSAI/QFI/TEID；配置N3传输保护和入口过滤；PFCP/OAM使用认证、完整性和变更审计；地面应用再次做飞机/会话/消息授权校验。
  • 来源： [1] TS 23.501；[7] TS 29.281；[8] TS 29.244；[4] TS 33.501。

4.7 F-07：N3/N6外层元数据和无应用TLS业务的被动监听（结论：C-F-07）

  • 协议/接口层级： Uu广播/初始接入、N3 GTP-U外层头、N6业务payload和应用层TLS；对应TS 38.331、TS 29.281、TS 23.501及部署侧安全方案。
  • 触发条件： 观察者具有Uu覆盖接收条件或进入N3/N6传输观察点；业务应用没有端到端TLS/消息加密，或者只保护了无线段而未保护地面出口。
  • 适配设备： 机载5G UE、ATG gNB、地面传输设备、UPF、N6交换/路由设备和地面应用。
  • 利用前提： 被动监听只需观察条件，不需驱动发送线；真实RF捕获和运营网络抓包不在本项目范围内。
  • 攻击路径： 观察广播和初始注册元数据；在N3观察点读取GTP-U外层头和TEID；在无应用TLS时解析业务payload；保存数据供后续重放或画像分析。
  • 具体业务影响： 暴露小区、会话、业务类型、飞机运行状态、机务记录或配置内容；元数据可帮助攻击者选择目标和时间窗口。监听本身不证明已经修改业务。
  • 危害分级： 中；真实维护配置、身份或运行数据敏感度较高时可升级为高。
  • 验证思路： 分别记录Uu广播/初始信息、N3外层字段和应用payload；开启/关闭应用TLS，比较传输观察点可读字段；不使用真实身份或生产数据。
  • 仿真证据： captures.uu.broadcast_sib_visible=True、pre_security_registration_metadata_visible=True；N3外层和TEID可见；无应用TLS时payload可读，有应用TLS时不可直接读取。
  • 整改措施： 关键业务采用端到端应用TLS或批准的消息加密；按部署安全要求保护N3/N6传输；最小化初始接入元数据；分离客舱、机务和航电日志；对观察点和调试抓包进行物理、逻辑和权限控制；禁止将演示流量带入生产。
  • 来源： [6] TS 38.331；[7] TS 29.281；[4] TS 33.501；[9]-[11]民航航空器网络安全指导。

4.8 F-08：客舱网络到机载航电边界的跨域注入（结论：C-F-08）

  • 协议/接口层级： 机载UE用户面、N6/机载数据适配器、客舱到航电安全网关及其下游协议代理；具体ARINC、以太网或串行接口必须按真实ICD另行确认。
  • 触发条件： 客舱DNN或客舱网络路由能够直接到达航电域；边界只检查网络可达、IP地址、TEID或“来自专属核心网”，没有消息类型、来源设备、命令权限和安全关键功能白名单。
  • 适配设备： 客舱交换/路由设备、机载5G UE、N6/机载安全网关、航电数据集中器、显示/FMS/其他LRU。
  • 利用前提： 攻击者先控制客舱终端、客舱应用、机载数据适配器或跨域网关；本报告不声称互联网或公网5G可以直接到达真实航电。
  • 攻击路径： ATG-UE-001的atg.cabin会话 -> CABIN源区 -> 合成AVIONICS_COMMAND -> 弱化路由直接调用航电消费者；加固网关在应用交付前拒绝。
  • 具体业务影响： 在真实系统若边界后存在写入型航电功能，可能执行未授权模式、配置或指令，影响显示、导航、告警或其他安全关键功能；当前模型只执行合成命令字符串，不代表真实机载功能已经改变。
  • 危害分级： 极高，但必须以真实ICD证明存在可写安全关键路径；只读遥测代理或隔离测试接口应按实际功能重新分级。
  • 验证思路： 建立客舱、机务、航电三个独立安全域；对每个DNN和消息类型做正向/负向矩阵测试；验证客舱命令无论是否带有正确传输标识都不能进入航电消费者，并检查下游没有副作用。
  • 仿真证据： 原生结果为accepted_trusted_transport且效果为avionics_command_executed:SET_FLIGHT_DISPLAY_MODE；加固结果为cabin_to_avionics_boundary，加固航电命令列表为空。
  • 整改措施： 默认拒绝客舱到航电写入路径；采用物理/逻辑分域、单向或只读代理、协议白名单、命令白名单、独立认证、速率和状态限制；任何跨域数据定义飞机、会话、方向、消息类型和安全目标；按ARP4754A/ARP4761A和DO-326A/DO-356A验证隔离失效模式。
  • 来源： [1] TS 23.501；[9] DO-326A/ED-202A；[10] DO-356A/ED-203A；[12] SAE ARP4754A；[13] SAE ARP4761A；[14] CCAR-25 §25.1309。

4.9 F-09：OAM/OSS或供应商跳板修改专属核心网路由（结论：C-F-09）

  • 协议/接口层级： 5GC OAM/OSS管理边界、网元配置、N4/PFCP转发规则和N6/机载跨域策略；OAM具体协议需按供应商ICD和安全架构冻结。
  • 触发条件： 维护跳板被视为“内网可信”，只凭网络位置、共享账号或未审计接口接受路由更新；没有mTLS、RBAC、双人审批、签名配置和边界不可绕过策略。
  • 适配设备： OAM服务器、供应商维护跳板、SMF/UPF、N6安全网关、地面应用和机载边界控制器。
  • 利用前提： 需要维护账号、跳板控制权、供应商工具权限或配置发布权限；不假定客舱用户可直接调用OAM接口。
  • 攻击路径： vendor_jump_host以vendor_support角色提交UPDATE_ROUTE_POLICY -> 弱化OAM直接把cabin_to_avionics_route打开、关闭切片隔离 -> 后续客舱数据沿新路由到达航电边界。
  • 具体业务影响： 隔离策略被配置层面拆除；攻击者不必攻破Uu加密就可能改变业务流向；维护审计、故障定位和持续适航记录失真。
  • 危害分级： 极高，因为它可能一次性改变多个业务和安全域的边界；真实后果仍取决于实际路由和下游功能。
  • 验证思路： 用合成OAM请求覆盖未授权来源、错误角色、缺mTLS、缺双人审批、错误签名、过期时间戳、重复序号和试图打开航电路由的授权请求；每种情况都应无配置副作用。
  • 仿真证据： 弱化OAM返回trusted_oam_bridge并接受路由变更；未授权加固请求返回oam_rbac；正确授权但试图打开边界也会被protected_boundary_policy阻止；正确的非跨域配置返回oam_authorized。
  • 整改措施： OAM独立于业务面；每个网元和管理员使用设备证书/mTLS和最小RBAC；敏感路由采用双人审批、签名配置、变更窗口、自动回滚、不可篡改日志和实时告警；安全策略控制器必须能拒绝越过航电边界的配置，即使请求来自授权管理员。
  • 来源： [8] TS 29.244；[9]-[11]DO-326A、DO-356A、DO-355；[14]CCAR-25 §25.1309。

4.10 F-10：机载5G UE的凭证、固件和本地边界被攻陷（结论：C-F-10）

  • 协议/接口层级： UE UICC/eSIM认证材料、NAS/RRC安全上下文、UE固件启动链、机载数据适配器和本地客舱/航电端口。
  • 触发条件： UE调试口开放、固件/配置未签名、信任锚可被替换、认证材料保护不足，或机载适配器把已认证的5G承载无条件映射到高权限本地接口。
  • 适配设备： 机载5G调制解调器、通信管理单元、UICC/eSIM、机载网络交换机、数据适配器和维护端口。
  • 利用前提： 需要设备维护接触、供应链/固件更新权限、被攻陷的机载应用或本地调试能力；不是只凭一个无线用户就能实现。
  • 攻击路径： 攻陷UE固件/本地桥 -> 使用合法网络凭证建立正常5GS会话 -> 通过已授权DNN发送异常应用流量或修改本地跨域映射 -> 地面/边界应用过度信任该流量。
  • 具体业务影响： 客舱宽带、机务回传和航电遥测的真实性失去；设备成为跨域注入跳板；密钥泄露会使单一UE的攻击影响扩大。
  • 危害分级： 高；若同一UE持有航电写入权限或可直接绕过边界，按极高评估。
  • 验证思路： 在离线UE安全台架检查安全启动、固件签名、信任锚、调试口、证书轮换和DNN权限；用合成已认证UE验证“网络认证成功”不能直接获得航电写权限。
  • 仿真证据： 本项目通过合成UE会话和来源密钥证明会话绑定/应用认证边界；未实现真实UE固件、UICC/eSIM或调试口漏洞，因此该条为设计审查和后续台架验证项。
  • 整改措施： 安全启动和签名固件；硬件保护密钥；禁用或受控调试口；UE profile最小权限；客舱和航电承载分离；本地适配器再做设备认证和命令授权；证书/密钥吊销、轮换和失效审计。
  • 来源： [3] TS 24.501；[4] TS 33.501；[9]DO-326A；[10]DO-356A；[11]DO-355。

4.11 F-11：地空gNB的广播、邻区和N2/N3配置错误（结论：C-F-11）

  • 协议/接口层级： NR系统信息、RRC小区选择/重选、NG-RAN到5GC的N2/N3接口、邻区和切换配置；对应TS 38.300、TS 38.331、TS 23.501。
  • 触发条件： gNB广播PLMN/TAC/ATG能力、邻区列表、N2/N3对端、证书、切片支持或空口参数配置错误；配置发布缺少签名、审批和一致性检查。
  • 适配设备： ATG gNB、地面站控制器、传输路由器、AMF/UPF、UE cell-selection策略和OAM系统。
  • 利用前提： 需要gNB配置权限、供应商维护权限或授权测试环境中的可控邻区；普通客舱用户不应拥有这些权限。
  • 攻击路径： 修改广播或邻区配置 -> UE选择错误/未信任小区，或gNB把流量送到错误N2/N3对端 -> 注册失败、用户面黑洞或错误安全域交付。
  • 具体业务影响： 空地业务中断、切换失败、初始注册元数据暴露、跨站点/跨飞机数据错误交付，地面监控难以判断问题来自空口还是核心网。
  • 危害分级： 高。
  • 验证思路： 运行配置静态检查和数字小区选择矩阵；对PLMN/TAC/ATG能力、邻区、N2/N3端点和切片配置做一字段变更，检查UE选择、核心会话和告警。
  • 仿真证据： 可信/恶意Cell ID的注册结果、广播可见和AKA失败状态已记录；真实gNB广播、N2/N3互通和RF覆盖仍为后续授权台架项。
  • 整改措施： gNB配置签名和双人发布；邻区/PLMN白名单；N2/N3端点证书和传输保护；禁止未授权切片/切换配置；持续监测小区身份、注册失败率、切换失败率和异常覆盖。
  • 来源： [1] TS 23.501；[5]TS 38.300；[6]TS 38.331；[9]-[10]DO-326A、DO-356A。

4.12 F-12：N6地面应用过度信任网络来源或缺少业务语义校验（结论：C-F-12）

  • 协议/接口层级： N6 IP接入、地面遥测/机务应用协议、消息schema、应用认证和数据库写入；对应TS 23.501的N6架构，具体业务协议按项目ICD。
  • 触发条件： 地面应用根据源IP、DNN、VLAN、TEID或“来自专属UPF”直接写入遥测/维护数据库，没有飞机、航班、会话、消息类型、范围、序号和授权校验。
  • 适配设备： UPF、N6防火墙、地面运行监视、机务数据平台、消息队列、数据库和告警服务。
  • 利用前提： 能到达N6入口、控制转发代理或发送一个合法格式的业务包；不需要攻破地面数据库本身。
  • 攻击路径： 进入N6 -> 发送合法JSON/业务字段 -> 弱化应用按可信传输写入状态；加固网关在应用交付前执行认证、时效、序号和语义范围检查。
  • 具体业务影响： 运行状态、机务记录、BITE结果或维护工单错误；错误数据被下游系统二次传播，形成跨系统一致性问题。
  • 危害分级： 高。
  • 验证思路： 对高度、空速、飞机标识、维护记录、命令类型、序号和时间戳分别构造越界、错配、旧包和未知枚举；验证数据库和下游告警不被拒绝数据改变。
  • 仿真证据： 用户面篡改、重放、TEID/QFI伪造和正常遥测的原生/加固结果形成前后对照。
  • 整改措施： N6采用mTLS或批准的消息级认证；schema和范围校验；飞机/航班/会话关联；消息去重、时间同步和隔离队列；维护写操作采用人工复核和双人控制；对拒绝包保留可审计但不影响业务安全域的证据。
  • 来源： [1] TS 23.501；[4] TS 33.501；[9]-[11]DO-326A、DO-356A、DO-355。

5. 攻击实现条件、技术路径和验证矩阵

5.1 攻击前提分级

为避免把通用网络攻击泛化到民航，本报告把攻击前提分为：

P0 被动观察 能观察Uu广播/初始信息或进入N3/N6传输观察点 只能证明元数据/明文暴露，不证明可注入

6.2 加固优先级

P0：飞行试验/运行前必须完成

  • 关闭客舱到航电的直接写路由，建立经过安全评估的只读或单向代理；
  • 禁止未授权OAM/供应商跳板修改UPF、DNN、切片和跨域策略；
  • 关键机务和运行数据启用经批准的应用层完整性与保密保护；
  • 定义Uu丢失、注册失败、切换失败和核心网不可用时的安全降级与独立备用源。

P1：联调和安全验证前必须完成

  • 完整绑定DNN、S-NSSAI、QFI、TEID、N3对端、UE和目标安全域；
  • 增加注册/服务请求/PDU会话限速、过载保护、重试上限和异常告警；
  • 完成UE/gNB/核心网/OAM配置基线、签名发布、证书轮换、日志和回滚测试；
  • 对伪小区状态、AKA失败、异常驻留、广播元数据和切换旧状态进行数字/屏蔽台架验证。

P2：持续运行和持续适航

  • 维护攻击面清单、供应商SBOM/CVE跟踪和补丁影响分析；
  • 定期做边界负向测试、配置漂移检测、密钥生命周期演练和事件响应演练；
  • 对真实飞行阶段、航迹、覆盖、切换和链路恢复数据进行趋势分析，但不把运营数据复制到实验环境。

6.3 加固验收准则

验收应以具体项目安全目标和适航数据为准。本项目给出可复现的数字基线：

  1. 可信UE在可信Cell上完成注册、5G-AKA、安全模式和合法PDU会话；
  2. 恶意Cell的广播和初始信息可被观察，但加固UE不驻留、不建立用户面；
  3. 50次同一时间注册请求中，受控模型最多分配10个合成上下文，其余被明确拒绝；
  4. 合法遥测通过；修改payload而保留旧认证值时返回authentication，且应用状态不变；
  5. 合法消息首次通过，完全重复消息返回replay；
  6. 修改TEID/QFI返回会话绑定错误，不能仅凭DNN完成交付；
  7. 客舱航电命令和试图通过OAM打开跨域路由均不能到达航电消费者；
  8. 无应用TLS时报告明确显示payload可读风险，有应用TLS时传输观察点不应直接读取payload；
  9. 所有测试输出记录模型版本、环境、时间、配置、输入变化、判定、业务副作用和限制。

7. 实验结果、局限和真实台架扩展

7.1 已完成的数字证据

已完成并通过自动化测试的内容：可信注册、恶意小区的前置可见性和AKA失败状态、数字化干扰、注册信令限速、用户面篡改、重放、TEID/QFI会话绑定、客舱到航电边界和OAM路由策略。

这些结果证明：在给定合成状态和安全策略下，弱化信任路径会把异常消息交给业务消费者，而分层网关可以在应用交付前拒绝；同时也证明了“广播可见”“N3外层可见”和“业务payload保密”是三个不同安全属性。

7.2 未完成且不能冒充已完成的验证

  • 真实射频干扰、伪基站、空口监听和传播/多普勒；
  • 真实gNB、5GC网元、SIM/eSIM、N2/N3/N4/N6协议互操作；
  • 真实机载UE固件、地空基站配置、核心网补丁和供应商OAM漏洞；
  • 真实客舱网络、航电安全域、ARINC/以太网/串行物理链路和LRU；
  • 真实切换、航迹覆盖、飞行阶段降级和持续适航运行数据；
  • 任何CVE对具体民航设备的可利用性，除非已获得厂商型号、版本、公告和授权复现条件。

7.3 授权真实台架建议

若竞赛允许进一步搭建实体/联仿台架，建议顺序为：

  1. 使用射频屏蔽箱或经批准的有线射频接口，部署测试UE、测试gNB/核心网和合成SIM，先验证注册、切片、N3/N6和OAM策略；
  2. 用可控网络损伤器或协议状态注入器模拟丢包、延迟、重复和切换，不使用开放环境干扰；
  3. 将地面应用、客舱网关和航电边界替换为合成LRU/仿真LRU，验证所有写路径默认拒绝；
  4. 只有在真实设备、频谱、维护授权、适航安全评估和回退方案齐全时，才进行实体UE、gNB或接口卡的受控互操作；
  5. 所有测试保留拓扑、固件、配置、密钥测试材料、抓包脱敏记录、日志、时间同步、判定和恢复记录。

该扩展仍不能直接证明真实飞机安全，真实系统结果必须进入项目网络安全评估、系统安全评估、软件/硬件保证和适航审定证据链。

8. 结论

5G-ATG的核心风险不在于“5G没有任何安全机制”，而在于民航部署容易把空口安全、专属核心网、DNN/切片隔离、N3传输、N6应用、OAM管理和客舱/航电分域混成一个“内部可信”边界。只要其中一个边界把网络可达性当成消息授权，攻击者就可能从信号不可用、初始接入信息暴露、信令资源消耗、用户面篡改/重放、会话混淆或管理配置变更影响业务。

本项目的数字证据给出可复核的整改闭环：正常合法业务仍可注册和交付；异常小区不建立用户面；信令风暴受到限速；TEID/QFI和应用消息受到绑定和认证；重放被拒绝；客舱到航电及OAM越界路径被阻断。下一步应以真实运营配置、机载ICD、飞行阶段安全目标和适航审定基础替换合成数据，完成授权的实体/协议台架验证。
