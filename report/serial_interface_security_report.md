# 第6题：RS-422、RS-232 等串行接口脆弱性深度分析

**作答场景：** 民用航空机载航电系统与地面维护系统的全双工串行通信场景  
**验证对象：** 合成的 RS-422 机载 LRU-LRU 链路、合成的 RS-232 GSE-LRU 维护链路  
**报告版本：** 1.0  
**验证日期：** 2026-08-24  
**危害分级：** 极高、高、中、低四级  
**结论性质：** 研究台架与竞赛验证结论，不构成具体机型适航批准、运行放行或真实飞机安全结论

## 摘要

RS-232 和 RS-422 解决的是串行电气接口和信号传输问题，不提供原生的消息来源认证、访问控制、加密、抗重放或业务语义校验。差分传输可以改善 RS-422 的抗共模干扰能力，全双工可以让两个方向同时传输，但这两个属性都不能证明“报文来自合法 LRU”或“维护命令已经被授权”。RS-232 的信号接地和维护连接器还会扩大地面保障设备、USB/串口转换器和线束接入的暴露面。

本报告建立两个严格限定的民航场景：

1. `RS422-AVIONICS-LRU`：合成 ADC LRU 向 FMS/显示 LRU 发送 `AIR_DATA_UPDATE`，反向方向发送导航参考数据；两对独立差分线代表全双工方向。
2. `RS232-GSE-MAINT`：合成批准地面保障设备向 Air Data LRU 发送 `LOAD_CONFIGURATION`、`CLEAR_BITE_LOG` 等维护命令；链路使用单独的 TX/RX 方向。

实验中的帧格式、命令码、LRU 名称、数据范围和业务状态均为合成项目 ICD，不代表某个真实飞机的接口控制文件。实验结果如下：

| 场景 | 原生/直接接收端 | 加固网关 | 证据结论 |
|---|---|---|---|
| RS-422 正常航电数据 | 接受 | 接受 | 合法帧能够进入合成 LRU |
| 物理监听 | 可解析 `AIR_DATA_UPDATE` 和数据字段 | 原生链路不提供保密 | 差分不等于加密 |
| 未授权注入 | 接受，合成高度变为 `500 ft` | `unauthorized_source` 拒绝 | CRC 有效不等于来源可信 |
| 修改数据并重算 CRC | 接受，`crc_valid_after_tamper=True` | `authentication` 拒绝 | CRC 不是消息认证码 |
| 重放 | 接受 | `replay` 拒绝 | 原生帧没有受控新鲜度 |
| RS-232 维护命令 | 直接端口接受并改变配置/日志状态 | 地面会话接受；空中状态 `maintenance_not_available` 拒绝 | 端口隔离和地面互锁是必要控制 |
| 9,600/115,200 bit/s 配置失配 | `rate_mismatch` 拒绝 | 由配置管理和端口监测处理 | 配置错误造成数据不可用 |
| 64 帧突发占线 | 接受 64 帧，合法帧延迟 `72.22 ms` | 拒绝 64 帧，合法帧从 `0 ms` 输出 | 无入口限速会违反时间预算 |

机器可读证据见 [`artifacts/serial_interface_results.json`](../artifacts/serial_interface_results.json)，归档记录见 [`artifacts/serial_interface_experiment_log.md`](../artifacts/serial_interface_experiment_log.md)。

## 1. 场景、架构与安全边界

### 1.1 机载航电 RS-422 场景

本实验将一条机载设备互连抽象为：

```text
合成 ADC_LRU                         合成 FMS_DISPLAY_LRU
     |                                          |
     |  TX+/TX-: AIR_DATA_UPDATE               |
     +----------------------------------------->|
     |                                          |
     |  RX+/RX-: NAV_REFERENCE_UPDATE           |
     |<-----------------------------------------+
```

配置为 `TIA-422-B` 研究 profile、`115200 bit/s`、UART `8N1`、两对独立信号对、全双工。这里的“RS-422”只表示差分电气接口边界；上层合成帧不是 TIA-422-B 原生定义，也不是任何真实飞机 ICD 的替代品。

典型攻击前提不是“任意无线网络即可注入”，而是攻击者已经满足以下至少一项：

- 获得目标 LRU 的发送侧控制权；
- 在设备互连、维护适配器、串行转换器或连接器处接入能够驱动该方向的接口；
- 攻陷一个把以太网、USB 或其他维护协议桥接到该串行方向的设备；
- 对差分线对进行被动高阻监听，并且另有主动发送路径可用于注入或重放。

### 1.2 地面维护 RS-232 场景

本实验将维护路径抽象为：

```text
批准 GSE / 维护笔记本
          |
          | RS-232 TX/RX，TIA-232-F，8N1
          v
     Air Data LRU 维护端口
```

该端口位于合成 `ground_maintenance_connector`，全双工但不是差分链路。真实飞机是否允许该端口在装机状态、通电状态或空中状态使用，必须由 AMM、WDM、设备安装图、维护配置和安全评估确认。本实验专门对比“端口直接暴露且原生接收”和“安全网关 + 地面会话 + 空中互锁”。

### 1.3 资产与安全属性

| 资产 | 安全属性 | 民航业务后果 |
|---|---|---|
| LRU-LRU 航电数据 | 真实性、完整性、新鲜度、可用性 | FMS/显示/告警计算使用错误或陈旧数据，触发错误状态或备用源切换 |
| 维护配置与校准数据 | 授权性、完整性、可追溯性 | 装机配置偏移、维护测试结果不可信、后续计算使用错误参数 |
| BITE/维护日志 | 完整性、可用性、审计性 | 故障证据被清除或伪造，影响故障定位和持续适航记录 |
| 串行链路内容 | 机密性 | 暴露设备状态、维护命令、校准信息和可重放的原始帧 |
| 端口和方向控制 | 访问控制、故障隔离 | 未授权 GSE、USB 转换器或桥接设备成为串行发送源 |

### 1.4 威胁主体与验证范围

| 编号 | 场景主体 | 具备能力 | 本报告验证 |
|---|---|---|---|
| T1 | 被攻陷的机载 LRU/串行桥 | 产生目标波特率和帧格式的字节流 | 是，直接提交合法 CRC 帧 |
| T2 | 被替换、误配置或被攻陷的维护适配器 | 连接维护连接器，向 TX/RX 方向发送字节 | 是，抽象为 GSE 直连和未知来源 |
| T3 | 具备线束/连接器接触条件的人员 | 被动监听或插入串行转换器 | 是，数字监听、注入和重放 |
| T4 | 配置/维护流程错误 | 改变波特率、端口启用状态或地面互锁状态 | 是，9,600/115,200 失配和空中维护命令 |

**排除项：** 本报告没有假定客舱网络、互联网或无线链路天然可以直达该串行线；没有把合成命令码套用到真实机型；没有进行物理电压、共模、端接、EMI/ESD、连接器或真实 LRU 试验。

## 2. 串行接口原理与原生安全边界

### 2.1 RS-232 与 RS-422 的区别

| 属性 | RS-232 维护链路 | RS-422 机载链路 | 安全含义 |
|---|---|---|---|
| 电气表达 | 单端信号与参考地 | 平衡差分信号 | 差分改善抗干扰，不提供身份或加密 |
| 本实验方向 | GSE↔LRU 一对 TX/RX | 两对独立 TX/RX 差分对 | 全双工允许两个方向独立观察和发送 |
| 典型接入点 | 维护连接器、串口转换器、GSE | LRU 连接器、线束、桥接器 | 接入路径必须由安装和维护架构控制 |
| 传输组织 | 点到点 | 本实验按点到点全双工建模 | 物理点到点不等于来源认证 |
| 原生认证 | 无 | 无 | 任何能产生合法电平/字节的发送端都可能被接收 |
| 原生加密 | 无 | 无 | 监听者可获取应用层明文 |
| 原生抗重放 | 无 | 无 | UART 序号若存在也不是自动安全状态 |
| 原生访问控制 | 无 | 无 | 端口启用、GSE 授权和地面互锁属于系统设计 |

RS-422 的差分接收器通常根据两条信号线的电压差判定逻辑状态；这不意味着接收器知道“哪个 LRU”驱动了该差分对。RS-232 的电平和参考地解决收发器互连问题，也不包含用户、角色或命令授权。两者都只提供承载边界，安全属性必须由上层协议、网关、物理隔离和系统架构提供。[1][2]

### 2.2 合成应用帧格式

为便于复测，本项目定义了独立于 RS-232/RS-422 电气标准的应用帧：

```text
SYNC(1) | VERSION(1) | TYPE(1) | SEQUENCE(4) | LENGTH(2)
        | JSON_PAYLOAD(N) | CRC16(2)
```

本实验命令码为：

| 命令 | 方向/消费者 | 合成业务含义 |
|---|---|---|
| `AIR_DATA_UPDATE` | ADC_LRU→FMS_DISPLAY_LRU | 高度、空速等合成航电状态 |
| `NAV_REFERENCE_UPDATE` | FMS_DISPLAY_LRU→ADC_LRU | 合成导航参考 |
| `BITE_LOG_READ` | GSE→Air Data LRU | 读取维护故障记录 |
| `LOAD_CONFIGURATION` | GSE→Air Data LRU | 装载合成校准/配置参数 |
| `CLEAR_BITE_LOG` | GSE→Air Data LRU | 清除合成维护日志 |
| `SET_MAINTENANCE_MODE` | GSE→Air Data LRU | 切换合成维护状态 |

`SEQUENCE` 在原生接收器中只作为普通字段解析，不被用作防重放状态；`CRC16` 是 `CRC-16/CCITT-FALSE`，只检测部分传输错误。帧没有 source ID、role、channel binding、时间戳 MAC、密钥标识或加密字段。因此“帧格式有效”不能推出“来源合法”或“命令当前有效”。

### 2.3 全双工的安全边界

全双工在数字模型中为每个方向维护独立的发送时钟。实验中 `ADC_LRU->FMS_DISPLAY_LRU` 和 `FMS_DISPLAY_LRU->ADC_LRU` 都从 `t=0` 开始发送，说明方向之间没有共享半双工仲裁。安全含义是：

1. 攻击者若能接入一条方向对应的 TX/RX 线对，可以只影响该方向；
2. 反向响应可能被监听、篡改或伪造；
3. “能够双向同时传输”不等于“每个方向有独立认证”；
4. 真实物理驱动器的争用、电平破坏和故障遏制必须另做电气台架验证。

## 3. 部署场景脆弱性

### 3.1 航电 LRU 互连配置

**脆弱点 D-01：串行端口默认信任任何合法字节流。** 设备按波特率、UART 格式、帧头、长度和 CRC 接收后直接把 payload 交给航电应用。若没有独立的来源、通道和会话绑定，替换的串行桥或被攻陷 LRU 可以复用同一帧格式。

**脆弱点 D-02：串行桥接器扩大信任边界。** USB-UART、以太网-串口、维护测试适配器或记录设备可能把外部数据桥接到 LRU TX 方向。桥接器如果没有端口白名单、命令 allowlist、身份认证和日志，物理隔离的串行链路会被上游接口绕过。

**脆弱点 D-03：方向和端口配置缺少变更控制。** 发送方向、波特率、8N1/奇偶、端口启用状态、终端匹配和 LRU 地址/设备选择如果由维护装载决定，错误配置或未经授权的配置更新可能造成持续数据不可用或把维护端口暴露到装机状态。

**脆弱点 D-04：差分线的抗干扰属性被误当成抗攻击属性。** 监听者只需使用适当的高阻差分接收前端即可观察两条线的逻辑差；这与改变共模电压或制造电气故障不同。差分信号不隐藏 payload，也不阻止主动桥接器产生新的合法波形。

### 3.2 地面维护系统

**脆弱点 D-05：维护连接器和 USB/串口转换器成为可驱动入口。** GSE、便携维护电脑、转接线和测试盒只要获得连接器访问权，就可能发送原生维护帧。若 LRU 只检查 CRC 和命令码，未知设备也能发出 `LOAD_CONFIGURATION` 或 `CLEAR_BITE_LOG`。

**脆弱点 D-06：空中/地面状态没有在安全边界强制执行。** “维护人员应只在地面操作”是运行程序约束，不能替代 LRU 或网关中的硬件/逻辑互锁。实验中直接接收端在 `AIRBORNE` 抽象状态下仍接受合成维护命令，而安全网关拒绝 `maintenance_not_available`。

**脆弱点 D-07：维护日志与配置操作缺少不可抵赖关联。** 原生帧没有用户、设备证书、会话、序号持久化或签名；攻击者可以清除日志、重放旧配置或制造看似合法的维护操作记录。

### 3.3 物理与时序配置

**脆弱点 D-08：波特率/格式/端接配置失配。** 本实验发送端为 `9,600 bit/s`、接收端按 `115,200 bit/s` 配置，数字接收器拒绝为 `rate_mismatch`。真实设备还可能表现为丢字、帧错误、间歇性工作或故障告警，必须用目标 LRU 和波形记录确认，不能把某个软件结果推广为所有设备行为。

**脆弱点 D-09：无发送配额和入口限速。** 全双工不提供安全调度。实验中 64 个 `BITE_LOG_READ` 直接排队，合法维护帧从 `72.22 ms` 才开始；若消费者的更新时间限为 `20 ms`，则时间预算被违反。

## 4. 攻击路径与深度脆弱性分析

危害分级按“当前合成场景能证明的结果”给出；若真实 ICD 显示数据进入更高等级功能，应依据该功能的 FHA/SSA 重新升级，不把本实验直接写成极高后果。

### 4.1 SI-01：物理监听造成航电/维护明文泄露

**协议层级：** RS-232/RS-422 电气承载 + UART 字节流 + 合成应用帧解码。  
**触发条件：** 攻击者能接触 RS-422 差分线对、RS-232 TX/RX/参考地、设备连接器或已连接的串行桥；链路处于工作状态。  
**适配设备：** RS-422 的 LRU 互连线束、串行桥接器、记录设备；RS-232 的 GSE 维护连接器和 USB-UART 适配器。  
**利用前提：** 仅被动读取不需要驱动线；主动注入另需目标方向的发送路径。  
**攻击路径：** 线束/连接器高阻探测 → 按已知 baud/UART 格式采样 → 查找 `0x7e` 帧头 → 解析长度、类型、payload 和 CRC → 保存可重放帧。  
**具体影响：** 暴露合成航电数据、LRU 状态、维护命令和配置参数；监听本身不改变飞行状态，但为后续重放和针对性篡改提供素材。  
**危害分级：中。** 若真实维护数据包含敏感配置或监听结果可直接支持关键命令，按系统安全评估升级。  
**仿真证据：** RS-422 捕获 `63` 字节，解码出 `AIR_DATA_UPDATE`、`altitude_ft=30000`、`airspeed_kt=440`，`confidentiality=False`。  
**整改：** 对外部/维护边界使用经批准的加密封装或在系统架构上做物理/区域隔离；密钥由安全架构管理。不能把 RS-422 差分、RS-232 电平或 CRC 当作保密措施。

### 4.2 SI-02：合法 CRC 的未授权 RS-422 数据注入

**协议层级：** RS-422 接收方向 + UART 应用帧 + LRU 业务状态更新。  
**触发条件：** 攻击者在 `ADC_LRU->FMS_DISPLAY_LRU` 方向提交合法帧头、合法长度和重新计算的 CRC；接收器无密码学来源认证。  
**适配设备：** 消费 `AIR_DATA_UPDATE` 的 FMS/显示类合成 LRU；真实对象必须以 ICD 和数据流图为准。  
**利用前提：** 需要已攻陷发射 LRU、串行桥、线束接入点或能驱动该 TX 方向的测试适配器；仅拥有远程网络权限不自动满足该前提。  
**攻击路径：** 串行适配器/受损桥 → 115200 bit/s、8N1 字节流 → RS-422 TX 方向 → LRU 校验 CRC → 应用更新数据。  
**具体影响：** 合成 LRU 将 `altitude_ft=500`、`airspeed_kt=80` 写入最后航电数据状态；真实系统可能出现错误显示、错误告警、错误计算、备用源切换或降级。是否进入飞控或导致失控必须依真实 ICD/FHA/SSA 证明。  
**危害分级：高。** 当前实验只证明关键数据真实性边界被突破，不证明真实运输机具体功能后果；若目标数据进入关键安全功能，应按真实安全分析评估是否升级为极高。  
**仿真证据：** 原生接收 `accepted=True`，effect 为 `air_data_updated:500ft@100ms`；相同 raw frame 经网关因 `unauthorized_source` 拒绝，`no_physical_output`。  
**整改：** 在 LRU 消费者前设置单一安全终止点；认证数据绑定 source、role、channel、message type、sequence、timestamp 和 native raw；输出侧禁止未授权第二发送路径。

### 4.3 SI-03：报文篡改后重算 CRC 绕过完整性误区

**协议层级：** 应用帧 payload + CRC16 传输错误检测。  
**触发条件：** 攻击者修改 `AIR_DATA_UPDATE` payload 后重新编码 CRC，或直接在桥接器中替换整帧；接收器没有 MAC/签名。  
**适配设备：** 仅以 CRC 判定有效性的机载 LRU、维护 LRU 和串行桥。  
**利用前提：** 能捕获原始帧并在发送侧重发修改后的帧；不需要获取安全密钥，因为 native frame 没有密钥。  
**攻击路径：** 捕获合法 frame → 修改高度/空速 → 重新计算 CRC16 → 通过 RS-422/RS-232 发送 → 原生接收器接受。  
**具体影响：** 伪造值通过传输错误检查，进入后续应用逻辑；维护场景下可装载错误校准或清除 BITE 记录。  
**危害分级：高。** 关键航电数据和校准参数需按真实功能后果评估；只读非关键诊断数据可降为中。  
**仿真证据：** `1000` 修改为 `500`/`90` 等 payload 后，`crc_valid_after_tamper=True`，原生端 `accepted=True`；网关返回 `authentication`。  
**整改：** 保留 CRC 作为线路错误检测，同时在安全边界对完整 native raw 和上下文计算经批准的认证标签。CRC、UART parity、帧头和长度检查都不能替代密码学认证。

### 4.4 SI-04：捕获帧重放导致陈旧航电状态或重复维护动作

**协议层级：** 应用消息时序和业务状态机。  
**触发条件：** 攻击者捕获一帧以前合法的 raw bytes，在序号未被原生接收器检查的情况下再次发送；目标应用缺少时间窗和持久化新鲜度状态。  
**适配设备：** 周期性空速/高度/导航数据消费者，以及 `LOAD_CONFIGURATION`、`CLEAR_BITE_LOG` 等维护命令消费者。  
**利用前提：** 先具备被动读取能力，再具备目标方向发送能力；单纯监听只造成信息泄露。  
**攻击路径：** 监听 → 保存 raw frame → 延迟/重复发送 → native LRU 按 CRC 和命令码接受。  
**具体影响：** 陈旧航电数据继续被使用，或维护操作被重复执行；日志和配置的时间关联被破坏。实际超时和冗余动作由机型 ICD 和系统安全设计决定。  
**危害分级：高（关键周期数据/维护配置条件性）。** 非关键状态可评为中。  
**仿真证据：** 安全网关首次接受同一 `AIR_DATA_UPDATE` envelope，第二次在时间窗内返回 `replay`；native 接收器在 `t=300 ms` 仍 `accepted=True`。  
**整改：** 使用每来源/通道/消息类型单调序列、受控时间窗和持久化启动计数；覆盖掉电、回滚、LRU 更换、双通道切换、维护会话重建和时钟异常。

### 4.5 SI-05：RS-232 维护端口暴露导致配置篡改和日志破坏

**协议层级：** RS-232 维护连接器 + 维护应用命令 + LRU 配置/日志状态。  
**触发条件：** 维护端口在设备可接入状态下启用，只依赖帧格式、命令码和 CRC，不要求 GSE 身份、授权角色、地面状态或维护会话。  
**适配设备：** 合成 Air Data LRU 的 GSE 维护端口、USB-UART 转换器和维护笔记本；真实适配性需由 AMM/WDM/ICD 确认。  
**利用前提：** 能接触地面维护连接器，或控制连接到该端口的 GSE/桥接器。  
**攻击路径：** 未授权串口设备 → `LOAD_CONFIGURATION`/`CLEAR_BITE_LOG` → LRU 原生接收 → 校准状态或 BITE 日志改变。  
**具体影响：** 仿真中直接 RS-232 接收器接受 `LOAD_CONFIGURATION`，把 `calibration_id` 设为 `CAL-ATTACK`、`offset_ft=500`；直接接收 `CLEAR_BITE_LOG` 后 BITE 条目变为 `0`。真实系统可能影响维护放行、故障定位和后续数据计算。  
**危害分级：高。** 配置和日志是安全相关维护资产；若真实命令可改变关键系统配置，应按审定基础和 FHA/SSA 评估是否升级。  
**整改：** 维护端口默认关闭；使用物理钥匙/继电器或受控 GSE 使能；仅在 `ON_GROUND`、授权维护会话和正确设备身份同时满足时开放；每个命令实施角色 allowlist、双人/审批策略、MAC、序列和审计；空中状态 fail-closed。

### 4.6 SI-06：全双工反向方向伪造和响应混淆

**协议层级：** 全双工方向控制 + 请求/响应应用状态机。  
**触发条件：** 攻击者能接入反向 TX/RX 方向，并伪造 `BITE_LOG_RESPONSE`、导航参考或设备状态响应；请求方未绑定响应与请求序列、来源和会话。  
**适配设备：** RS-422 双向 LRU 互连、RS-232 GSE 请求/响应维护会话。  
**利用前提：** 必须控制对应反向线对、设备 TX 端或串行桥；不是只监听正向数据即可完成。  
**攻击路径：** 监听请求 → 在独立反向方向发送格式正确响应 → 消费者按 message type/CRC 接受 → 错误状态被当作真实结果。  
**具体影响：** 维护人员看到伪造的 BITE 结果，或 LRU 对错误状态做出错误切换/告警；可能破坏审计和故障定位。  
**危害分级：中到高，取决于响应是否参与安全相关决策。** 本报告验证了独立方向时钟和帧承载，但未把该项伪造响应写成真实 LRU 业务后果。  
**整改：** 请求/响应绑定同一 session、request ID、source、role、nonce/sequence 和 MAC；拒绝没有对应请求或已过期的响应；维护界面显示设备身份和会话审计结果。

### 4.7 SI-07：波特率失配造成航电数据不可用

**协议层级：** UART 时序/接口配置层。  
**触发条件：** 发送端为 `9,600 bit/s`，接收端按 `115,200 bit/s`、`8N1` 解码；或者维护配置被错误装载。  
**适配设备：** 维修更换后的 LRU、串口转换器、GSE 配置文件、测试盒和桥接网关。  
**利用前提：** 能改变端口配置、替换设备或在桥接器上选择错误 profile；也可能由维护错误造成。  
**攻击路径：** 配置边界 → 修改 baud/UART 参数 → RX 帧采样失配 → CRC/帧格式错误或静默丢帧 → 应用超时/备用源切换。  
**具体影响：** 数据不可用、维护操作失败、故障告警和备用模式；真实 LRU 表现必须通过目标台架和波形确认。  
**危害分级：中。** 若失配切断关键周期输入，应按实际时限和失效后果升级。  
**仿真证据：** 数字接收器对 `9,600` 发送、`115,200` 期望的帧返回 `rate_mismatch`，发送帧的数字线时长为 `13.541667 ms`。  
**整改：** 配置签名/版本控制、端口白名单、启动自检、baud lock 监测、帧错误计数、速率告警和安全降级；维护变更纳入持续适航和配置审计。

### 4.8 SI-08：突发发送造成串行链路时延和业务超时

**协议层级：** 串行 FIFO、发送调度和应用更新时间预算。  
**触发条件：** 能驱动维护 TX 方向的设备连续发送 64 个格式有效的 `BITE_LOG_READ`，原生链路没有发送配额、入口限速或可信调度。  
**适配设备：** RS-232 GSE 维护端口、串行转换器和处理周期受限的 LRU。  
**利用前提：** 活跃发送能力；被动监听不能产生占线。  
**攻击路径：** 攻击适配器 → 连续合法帧 → 单方向发送 FIFO → 合法维护帧排队 → 20 ms 业务期限违约。  
**具体影响：** 维护操作延迟、响应超时、状态机重试、日志混乱；对于时间关键航电数据，可能触发备用源或降级。  
**危害分级：高（时间预算条件性）。** 若有独立链路和快速超时可降为中。  
**仿真证据：** 原生端接受 `64` 个攻击帧，合法帧在 `72.22 ms` 开始，超过 `20 ms` 期限；网关拒绝 `64` 个攻击封装，授权合法帧从 `0 ms` 输出。  
**整改：** 入口按来源/命令限速，合法优先级和配额，异常占用告警；使用物理发送使能、隔离继电器或 bus guardian 类设计阻断绕过网关的第二发送路径；对所有控制做误拒绝和故障遏制分析。

## 6. 整改与加固方案

### 6.1 架构级边界

1. **单一安全终止点：** RS-232 GSE 和任何跨域 RS-422 桥接在进入安全相关 LRU 前经过受控网关。网关只输出批准的 native 帧，输出侧不提供可被第二设备并联驱动的旁路。
2. **物理隔离与端口使能：** 维护连接器默认关闭；使用飞机地面状态、维护钥匙/继电器、GSE 身份和会话同时控制。端口状态应有独立监测和审计。
3. **分区与方向策略：** RS-422 两个方向分别定义来源、消费者和允许消息；反向响应不能因为“同一根串行电缆”自动获得信任。
4. **桥接器最小化：** USB-UART、以太网-串口、记录器和测试盒只允许批准 profile、波特率、命令集合和方向；禁止透明任意字节转发。

### 6.2 报文级保护

建议采用系统级安全封装，而不是修改 RS-232/RS-422 电气标准：

```text
source | role | channel | message_type | native_raw
       | sequence | timestamp | session_id | approved MAC
```

- MAC 覆盖完整 native raw 和所有上下文，防止跨通道、跨角色和跨命令搬运；
- 每个 source/channel/message type 维护单调 sequence，处理掉电、回绕、双机更换和维护会话恢复；
- timestamp 只作为窗口控制的一部分，不替代持久化序列和会话状态；
- role 与命令 allowlist 分开校验，GSE 不应自动获得机载 LRU 数据发布权限；
- 语义策略来自真实 ICD：范围、变化率、更新周期、状态转移和失效动作；
- CRC/UART parity 保留用于随机线路错误检测，但不作为认证依据；
- 算法、密钥生命周期、硬件保护和失效策略必须由项目安全架构和适航审查确定。本项目 HMAC 仅用于可重复实验，不是直接装机方案。

### 6.3 业务和运维控制

- `LOAD_CONFIGURATION` 采用签名配置包、版本回滚保护、双人复核和装载后读回校验；
- `CLEAR_BITE_LOG` 只允许经授权的维护会话，必须形成不可抵赖审计事件，不能作为普通无状态命令；
- GSE 设备证书、固件版本、配置 profile 和串口转换器序列号进入白名单；
- 记录认证失败、未知 source、CRC 错误、波特率失配、重放、速率超限和端口启停事件；
- 监测到异常时采取经安全分析批准的 fail-safe/fail-silent 或备用源切换，不因安全过滤器故障产生新的危险输出。

### 6.4 物理与电气验证

软件模型不能替代以下台架项目：

- RS-232 电平、参考地、隔离、短路和串口转换器行为；
- RS-422 差分幅度、共模范围、端接、线缆长度、开路/短路、驱动争用和接收阈值；
- 8N1/其他 UART 格式、波特率容差、字节间隔、FIFO 溢出和时延分布；
- 监听探头的负载、主动注入器的故障遏制、EMI/ESD 和接地路径；
- 真实 LRU ICD、维护程序、地面互锁、配置装载和 BITE 日志响应。

## 7. 风险分级与符合性闭环

| 分级 | 本题适用判据 |
|---|---|
| 极高 | 真实机型证据证明未授权串行数据可直接导致灾难性功能后果，且攻击路径可在相关运行状态使用；本报告没有达到该证据条件 |
| 高 | 可影响安全相关航电数据真实性、维护配置完整性、关键时间预算或故障证据，路径已明确但真实功能后果仍需 ICD/FHA/SSA 确认 |
| 中 | 造成维护、显示、非关键数据或可恢复可用性影响，具有明确业务后果但不直接破坏关键功能 |
| 低 | 影响受限、易发现且不进入安全相关消费者，或仅为缺乏安全属性但无可利用接入路径的理论缺陷 |

本报告的高、中等级均是条件性场景分级。正式型号分析需要将每条串行消息映射到系统功能、DAL/安全目标、更新时间和失效状态，再由 FHA/SSA 和航空器信息安全过程确认最终分级。

## 8. 结论

RS-232/RS-422 的差分、全双工和点到点特征解决的是信号传输与方向组织，不提供密码学信任。只要攻击者满足物理接入、被攻陷 LRU、串行桥接器或维护设备这一明确前提，就可能监听明文、发送合法 CRC 帧、篡改并重算 CRC、重放历史帧，或利用维护端口执行配置/日志操作。实验还证明，错误波特率会使输入不可用，连续发送会使合法帧突破业务时限。

可落地的整改不是简单增加 CRC 或“更换差分线”，而是物理端口隔离、方向控制、GSE 身份与地面互锁、认证/抗重放封装、ICD 语义校验、速率和占用监测、配置生命周期及审计的组合。当前实验完成的是数字协议和业务状态边界验证；形成民航型号级结论还必须补充真实 ICD、真实 LRU、实体接口卡、线束/波形/EMI、维护程序和适航过程证据。
