# 链路三：地面网络接入型攻击链分析与验证报告

**题目：** 民航地面网络接入型攻击链（链路三）  
**版本：** 1.0  
**日期：** 2026-09-11  
**结论性质：** 本地数字模型复核、既有报告记载与工程推演的组合；不构成真实飞机、机场生产网、运营商5GC或适航结论。

## 摘要与结论

本链路讨论的不是“进入互联网即可进入飞机”，而是一个有条件的跨域路径：攻击者先取得地面保障网络、供应商维护跳板、5GC OAM/OSS或串口服务器管理面的初始权限，再利用错误的管理授权、路由/DNN/切片策略或串行桥接配置，把数据送入地面应用、维护边界或协议网关，最终影响机载数据消费者、维护放行数据或地面运行系统。

最小可行攻击链为：

```text
G3 地面网络初始权限
  -> G4 供应商跳板/OAM/串口服务器
  -> G5 核心网、网关路由或维护策略变更
  -> G6 N6/维护应用过度信任
  -> G7 串行/ARINC 429 跨协议网关
  -> G8 机载数据消费者、维护放行数据或地面运行系统
```

**结论：** 最危险的共同节点是管理平面到跨域出口的授权变更（G5），而不是初始进入地面网络本身。若 G5 被 RBAC、mTLS、双人审批、签名配置、不可绕过的边界网关和变更审计阻断，后续节点不可达。若真实系统只提供只读监视代理、没有向航电或维护执行面输出，影响应从“极高/高”降级；若存在可写的协议网关且下游消费者缺少来源认证，风险可升高。

本报告复用以下本地证据：

- 5G-ATG：OAM 路由变更、DNN/TEID/QFI 会话绑定、N6 用户面篡改/重放、客舱到航电边界；见 `artifacts/5g_atg_results.json`、`report/5g_atg_security_report.md`。
- 串行接口：RS-232 维护命令、重算 CRC 篡改、重放、波特率失配、突发占线；见 `artifacts/serial_interface_results.json`、`report/serial_interface_security_report.md`。
- ARINC 429：未授权来源、重放、重算奇偶、连续占线、速率失配；见 `artifacts/results.json`、`report/arinc429_security_report.md`。

这些证据证明合成模型中的状态判定，不证明任何真实机型存在该路径或已经被攻破。

## 1. 民航业务场景、资产与最终破坏目标

### 1.1 场景

分析对象是航空公司/机场保障组织、供应商维护组织与专属5G-ATG地面核心网共同支撑的航班运行和持续适航数据链。典型业务包括：航班运行监视、机务遥测回传、故障记录读取、配置/校准装载、维护放行数据生成，以及经严格隔离的机载数据消费者输入。

最终目标按影响递增排列：

1. 伪造或延迟航班运行监视、机务遥测和告警数据；
2. 篡改、重放或清除维护记录，使放行判断和故障定位失真；
3. 通过跨协议网关向合成机载数据消费者提交未授权数据；
4. 在真实 ICD 证明下，影响安全相关计算输入。当前项目没有证明第4项对具体飞机成立。

### 1.2 资产与域

| 资产 | 所属域 | 接口/协议 | 保护属性 |
|---|---|---|---|
| 企业/互联网入口 | 企业网/外部域 | IP、VPN、身份服务 | 身份、边界、审计 |
| 地面保障工作站和串口服务器 | 保障网 | SSH/管理API/RS-232桥 | 最小权限、设备身份、命令授权 |
| 供应商跳板 | 供应商维护域 | 受控远程维护协议 | 强认证、审批、会话记录 |
| AMF/SMF/UPF及OAM/OSS | 5GC/OAM域 | N2/N3/N4/N6、管理面 | 配置完整性、路由隔离、变更控制 |
| N6应用与运行监视 | 地面业务域 | 应用消息、TLS/消息认证 | 来源、飞机/会话绑定、抗重放 |
| 客舱/航电边界网关 | 机载跨域域 | 白名单代理/单向通道 | 默认拒绝、方向、字段和速率 |
| 串行/A429桥接器 | 维护/航电接口域 | RS-232/422、ARINC 429 | 物理使能、来源认证、ICD语义 |
| 机载数据消费者和放行数据 | 航电/持续适航域 | 合成项目ICD | 真实性、完整性、新鲜度、可追溯性 |

## 2. 完整系统架构与信任边界

### 2.1 系统架构图

```text
 [互联网/企业网]
        |
 B0 外部边界：身份、VPN、入口ACL
        v
 [地面保障网络] ---- [机场/航空公司运维SOC]
        |                         |
 B1 保障边界：跳板白名单、终端态势、工单授权
        v                         v
 [供应商维护跳板] ---- [5GC OAM/OSS]
        |                         |
 B2 管理边界：mTLS/RBAC/双人审批/签名配置/审计
        v                         v
 [串口服务器/GSE]       [AMF-SMF-UPF/N4]
        |                         |
 B3 接口边界：端口使能/维护状态/命令授权      [N3/GTP-U]
        |                         |
        +------------> [N6应用/运行监视/机务平台]
                              |
                       B4 业务边界：飞机、会话、消息认证、重放防护
                              v
                      [客舱/维护/航电跨域网关]
                              |
                       B5 航电边界：默认拒绝、单向/只读/字段白名单
                              v
                 [串行桥] ---- [ARINC 429 TX/RX]
                              |
                              v
                 [机载数据消费者/维护放行数据]
```

### 2.2 信任边界说明

| 边界 | 不得直接继承的信任 | 必须独立验证 |
|---|---|---|
| B0 互联网/企业网→保障网 | 网络可达不等于维护身份 | 用户、设备、工单、终端状态 |
| B1 保障网→供应商/OAM | 内部账号不等于变更授权 | 角色、时间窗、审批、命令范围 |
| B2 OAM→5GC路由 | 专属核心网不等于逻辑隔离 | 配置签名、DNN/S-NSSAI/UPF绑定、回滚 |
| B3 维护网络→串口服务器 | 能登录服务器不等于能驱动端口 | 端口、方向、地面状态、命令白名单 |
| B4 N6→业务应用 | 源IP、TEID、QFI不等于消息来源 | 飞机/会话/序号/时间/MAC或签名 |
| B5 网关→航电/维护执行面 | 客舱、地面或维护“内部可信”不成立 | 明确业务授权、只读/单向约束、原生输出控制 |

因此，“进入地面网络”只能使攻击者到达某个候选入口；每一道边界都可能终止链路，且不同边界需要不同证据。

## 4. 编号化攻击链

### 4.1 节点与边

| 节点 | 资产/域 | 接口与协议 | 攻击前权限 | 利用后权限 |
|---|---|---|---|---|
| G1 | 外部操作者 | 互联网/企业网身份面 | 无目标系统权限 | 可能获得低权限企业账号或入口可达性 |
| G2 | 地面保障网络 | VPN、堡垒机、管理网 | 保障网普通访问 | 可探测或访问维护服务；不应能改配置 |
| G3 | 供应商跳板/OAM或串口服务器 | 管理API、SSH、串口服务器控制面 | 受限维护会话 | 若控制失效，可取得某一跳板/端口管理权限 |
| G4 | 5GC路由与策略 | OAM、N4/PFCP、DNN、S-NSSAI、N6 ACL | 只读配置查看 | 错误或未授权的路由/切片/策略变更能力 |
| G5 | N6应用/运行监视/机务平台 | N6应用消息、GTP-U外层、TLS/消息认证 | 业务提交或只读 | 伪造、篡改、重放业务消息，或改变数据落点 |
| G6 | 客舱/航电边界网关 | 跨域代理、白名单、单向通道 | 不应有航电写入权 | 若边界失败，可提交合成航电命令/数据 |
| G7 | 串行/A429桥接器 | RS-232/422、ARINC 429 | 维护数据或只读桥接 | 可产生合法CRC/奇偶的原生帧 |
| G8 | 机载消费者/放行和运行系统 | 合成ICD、应用状态 | 接收合法业务输入 | 接收错误/陈旧维护或运行数据；后果由真实ICD决定 |

```text
E01 G1 -> G2：凭据/远程维护入口被接受（工程推演）
E02 G2 -> G3：跳板、OAM或串口服务器横向访问（工程推演）
E03 G3 -> G4：变更路由、DNN/切片或维护策略（ATG-V09/ATG-V12）
E04 G4 -> G5：N6转发到过度信任应用（ATG-V12）
E05 G5 -> G6：跨域网关未按业务域拒绝（ATG-V06）
E06 G6 -> G7：协议代理把业务数据转为原生帧（SER-V09/SER-V10/A429-V05）
E07 G7 -> G8：原生消费者按CRC/奇偶/标签接受（A429-V05/A429-V06）
```

任意 E01-E03 的身份、物理接入、审批或网络路径不成立，链路即中断；任意 E05-E07 有独立默认拒绝和物理发送使能，不能把前一步权限自动升级为航电写入权。

### 4.2 典型分支

**分支 A：OAM→N6→跨域网关。** G3取得OAM变更能力后，修改UPF/N6路由或DNN/S-NSSAI映射；G5应用错误接受伪造/重放遥测；若客舱到航电边界错误放行，进入G6。对应ATG-V09、ATG-V12、ATG-V06。

**分支 B：跳板→串口服务器→维护命令。** G3取得串口服务器端口控制后，向RS-232维护端口提交合法格式命令；若设备只检查CRC且未执行地面互锁，G7可改变配置、清除BITE或产生维护数据。对应SER-V09、SER-V10。

**分支 C：维护/应用网关→ARINC 429。** G6或G7把输入转换为标签正确、奇偶正确的ARINC 429字；原生接收端可能无法验证来源、新鲜度和语义。对应A429-V05、A429-V06。该分支必须有真实桥接器、端口方向和ICD证据，不能从网络可达性推断成立。

## 5. 前提、设备、能力与时间

| 阶段 | 触发前提 | 所需设备/能力 | 准备时间 | 实施时间 | 保持访问 |
|---|---|---|---:|---:|---:|
| 初始地面入口 | 有效账号、维护窗口或物理保障网位置 | 普通终端、经批准的VPN/跳板客户端 | 天到周 | 分钟到小时 | 受会话和工单限制 |
| 跳板/OAM | 供应商身份或被攻陷维护工作站 | 管理终端、配置阅读能力 | 周到月 | 分钟到小时 | 需持续会话/令牌 |
| 路由/策略变更 | 变更权限或配置发布绕过 | 5GC/OAM知识、策略理解 | 周到月 | 分钟到小时 | 配置持久化前后不同 |
| N6/业务伪造 | 可到达应用或桥接器且缺少端到端认证 | 协议和ICD理解、消息构造能力 | 天到周 | 秒到小时 | 取决于序号/会话 |
| 串口/A429输出 | 真实端口、GSE或桥接器可驱动 | 专用适配器、目标波特率/速率和ICD | 周到月 | 秒到分钟 | 需物理连接或输出侧控制 |

**瓶颈：** 真实系统中最难证明的是 E03 的可写管理授权、E05 的跨域输出，以及 E06 的物理/逻辑发送能力。知道DNN、TEID、标签或命令码不等于获得权限；本地合成模型不替代这些证据。

## 6. 可观测性、告警与检测条件

| 步骤 | 应记录的日志/传感器 | 告警条件 | 可检测阻断 |
|---|---|---|---|
| G1/G2 | IAM登录、VPN、终端态势、源位置 | 异常地理位置、失败次数、非工单访问 | 身份吊销、MFA、网络隔离 |
| G2/G3 | 跳板会话、命令审计、录屏、工单号 | 非维护窗口、角色与命令不匹配 | 会话审批、命令白名单 |
| G3/G4 | OAM配置diff、PFCP/N4、DNN/S-NSSAI变更 | 单人变更、未签名配置、路由跨域 | 双人审批、签名、回滚、基线比对 |
| G4/G5 | N3/N6流量、TEID/QFI、应用序号、飞机/航班绑定 | 绑定不一致、重放、突变速率 | 丢弃、隔离、密钥/会话吊销 |
| G5/G6 | 跨域网关决策、方向、字段和目标域 | 客舱/维护到航电写入尝试 | 默认拒绝、只读代理、单向出口 |
| G6/G7 | 网关输出、串口帧、A429标签/速率/奇偶 | 未授权源、CRC/奇偶合法但认证失败、突发占线 | 物理发送使能、限速、bus guardian类控制 |
| G7/G8 | LRU接收计数、超时、冗余比较、BITE | 陈旧序号、语义越界、更新率异常 | 冻结/切换/告警，按安全分析决定 |

本链路的高价值检测点是 G3/G4 的**配置变更审计**和 G6/G7 的**实际输出审计**。只记录登录成功不足以证明阻断；必须记录“请求是否到达应用、是否转发、是否产生原生输出、是否被消费者使用”。

## 7. 风险量化模型

### 7.1 参数定义

不使用CVSS替代航空业务风险，也不把多个主观概率相乘成伪精确成功率。每条链路分别给出等级和区间。

- **设备成本 C：** 1低（通用终端/软件）至5高（专用GSE、串口/A429适配器、授权台架）。
- **技术门槛 T：** 1为一般网络操作；2为管理面基础；3为5GC/OAM或串行协议理解；4为跨域策略和ICD理解；5为真实设备、时序、冗余和安全分析能力。
- **时间成本 P：** 准备、实施、保持访问分别记录，不合并。
- **接入难度 A：** 1为远程可达；3为需保障网/维护窗口；5为需实体端口、在场设备或飞行器台架。
- **被检测概率 D：** 给出区间并说明传感器依据；无真实数据时标注为分析模型估计。
- **业务影响 I：** 低/中/高/极高，按是否到达写入边界、维护放行数据或安全关键消费者调整。

### 7.2 场景评级

| 分支 | C | T | A | D（分析模型估计） | I | 攻击可行性判断 |
|---|---:|---:|---:|---|---|---|
| A OAM→N6→跨域 | 2-4 | 4-5 | 3-4 | 70%-95%，OAM diff/审计/网关日志可见 | 高；真实航电写入时极高 | 瓶颈是可写OAM和跨域错误放行 |
| B 跳板→RS-232维护 | 2-4 | 3-4 | 3-5 | 60%-90%，端口日志和BITE变化可见 | 高 | 瓶颈是实体/服务器端口和地面互锁失效 |
| C 网关→ARINC 429 | 4-5 | 4-5 | 4-5 | 50%-90%，取决于认证、接收计数和冗余监视 | 高；关键消费者时极高 | 瓶颈是真实桥接器、方向和ICD |

D区间不是实验测得概率，而是基于“有/无IAM、变更审计、N6认证、网关决策和LRU监视”的分析估计；必须用目标系统日志和授权台架校准。设备成本也只表示类别等级，不是假定市场报价。

### 7.3 敏感性分析与最小阻断点

| 条件变化 | 链路结果 | 影响评级变化 |
|---|---|---|
| 无法进入保障网或无合法维护身份 | G1→G2中断 | 由路径不可达转为仅理论风险 |
| 有保障网但无跳板/OAM/串口授权 | G2→G3中断 | 不应升级到配置或输出风险 |
| OAM可读但不可写，配置需双人签名 | G3→G4中断 | ATG-V09分支基本终止 |
| N6应用强制飞机/会话绑定和抗重放 | G4→G5数据分支中断 | 遥测伪造/重放降为可用性或无效 |
| 航电边界默认拒绝且仅只读 | G5→G6中断 | 航电写入影响降级，仍需评估地面数据 |
| 串口端口物理断开/空中互锁 | G6→G7中断 | 维护命令分支不可行 |
| A429安全网关认证、限速、单一输出 | G7→G8恶意帧中断 | 原生协议缺口不再直接暴露给消费者 |
| 真实ICD不允许该标签/命令到达目标消费者 | G7→G8语义中断 | 该具体影响不成立 |

**最小阻断点：** 在 G3/G4 设置经过签名和双人审批的配置发布控制；在 G5/G6 设置不可绕过、默认拒绝的跨域业务网关；在 G6/G7 设置物理/逻辑单一受控输出。三者中任一点有效，整条链不能无条件闭合。

## 8. 证据等级与复核结果

| 结论 | 证据等级 | 依据 |
|---|---|---|
| OAM未授权路由变更可被加固模型拒绝 | 本地复核 | `5g_atg_results.json` 的 `oam_route_change`，原因 `oam_rbac` |
| TEID/QFI错误不能仅靠标识符获得会话信任 | 本地复核 | `session_binding`，加固原因 `session_binding`/`qfi_binding` |
| N6篡改/重放可被应用层认证和序号拒绝 | 本地复核 | `data_tamper`、`data_replay` |
| 客舱到航电边界应独立授权 | 本地复核 | `cabin_to_avionics_boundary` |
| RS-232空中维护应拒绝 | 本地复核 | `serial_interface_results.json`，原因 `maintenance_not_available` |
| CRC重算不提供来源认证 | 本地复核 | `tamper_recomputed_crc`，加固原因 `authentication` |
| A429奇偶重算不提供认证 | 本地复核 | `results.json`，加固原因 `authentication` |
| 地面网络到真实飞机存在可写路径 | 待实装验证 | 缺少真实拓扑、账号矩阵、维护流程和端口/ICD证据 |
| 具体飞机的最终飞行安全后果 | 待实装验证 | 缺少型号FHA/SSA、真实消费者和独立遏制证据 |

## 9. 不成立条件、阻断点与待补真实证据

### 9.1 不成立条件

- 初始账号只是企业网普通账号，不能到达保障网或维护跳板；
- OAM、N4/PFCP和路由配置均由签名、双人审批和不可回滚旁路的发布系统保护；
- N6应用执行飞机、航班、会话、序号、时间窗和消息认证；
- 客舱/维护到航电只有只读、单向或字段级代理；
- 串口服务器没有可驱动的机载端口，或地面/空中状态由硬件互锁强制执行；
- ARINC 429输出侧仅有一个受控发射端，网关外无法旁路；
- 真实ICD证明相关数据不进入安全关键消费者。

### 9.2 需要补齐的证据

1. 真实地面网络、保障网、供应商网络、OAM和N6拓扑及ACL；
2. 账号、角色、MFA、跳板、工单、双人审批和应急账号矩阵；
3. AMF/SMF/UPF、N4/PFCP、DNN/S-NSSAI/QFI/TEID的配置基线和变更审计；
4. N6应用ICD、TLS/消息签名、飞机/航班/会话绑定、重放状态持久化；
5. 客舱/航电网关数据流、方向、白名单、旁路测试和失效安全策略；
6. 串口服务器、GSE、维护连接器、地面状态互锁及日志链；
7. ARINC 429桥接器的发射使能、标签策略、速率、冗余源和真实接收消费者；
8. 真实机型FHA/SSA、维护放行流程、告警响应和运行降级证据。

## 10. 防御性验证设计与验收条件

验证只在离线数字模型、隔离网络或批准台架进行，不连接机场生产网、运营商公网、真实飞机、空管网或公共频谱。

| 验证项 | 输入 | 通过条件 |
|---|---|---|
| V3-01 管理变更 | 未授权OAM路由/DNN策略请求 | 无配置生效；有完整审计和告警 |
| V3-02 会话绑定 | 错误TEID/QFI、跨飞机/跨DNN消息 | 无应用投递、无数据库副作用 |
| V3-03 N6完整性 | 修改payload、旧序号、旧会话消息 | `authentication`或`replay`拒绝 |
| V3-04 跨域边界 | 客舱/维护向航电提交写入请求 | 默认拒绝；只读允许项不产生写入 |
| V3-05 维护互锁 | 空中状态的配置/BITE命令 | `maintenance_not_available`；无状态改变 |
| V3-06 串行/A429输出 | 合法CRC/奇偶的未知来源帧 | 网关拒绝；无原生输出或消费者更新 |
| V3-07 审计闭环 | 从登录到网关输出的完整事件链 | 可关联用户、设备、工单、会话、目标和结果 |

现有数字证据可直接复核 V3-02、V3-03、V3-04、V3-05、V3-06 的合成版本；V3-01和V3-07仍需接入真实配置发布与审计系统验证。
